# 003. 새 문서 만들기: 빈 문서 템플릿·스타일·표·양식 비우기

## 상황

SPEC-003(새 문서 만들기)의 기능 이슈(#36~#39)에 들어가기 전에, `@rhwp/core` 0.8.7 공개 API 로 다음이 스펙대로 되는지 확인해야 했다(#35).

- `createBlankDocument()` 문서의 스타일 목록(제목·개요 1~7·본문 등이 있는지), 개요 번호, 블록 추출(SPEC-001), HWPX 저장 검증(SPEC-002)
- `applyStyle` 로 문단·글자 모양이 스타일대로 바뀌는지, 직접 서식과 섞일 때
- `createTable`/`createTableEx`: 넣는 위치, 열 너비, 칸 글자·칸 안 여러 문단, 머리글 행 표현
- 양식 파일 본문 비우기: 구역 첫 문단 남기기, 본문 표·그림·글상자 지우기, 머리말·꼬리말 유지
- 열린 질문 3개(path 필수 여부, 머리글 표현, 양식 본문의 표·그림)

확인은 프로토타입 함수(`src/core/create-document.ts`)와 테스트(`tests/create-spike.test.ts`, 묶음 `SPEC-003 … (기술 검증)`), 한글 확인 파일 생성 스크립트(`scripts/make-create-check.ts`)로 했다. rhwp 소스는 `v0.8.7` 태그로 읽었다(`src/document_core/commands/formatting.rs` `apply_style_native`, `object_ops/table.rs` `create_table_*`, `parser/hwpx/header.rs`).

## 결정

**rhwp 기준 GO, 한글 프로그램 확인 대기.** 아래 방식으로 만든다. 사용자가 `~/Downloads/docbridge-create-check/` 파일을 한글에서 열어 경고가 없고 스타일·개요 번호·표가 맞으면 이 ADR 을 accepted 로 바꾼다. 경고가 나면 "NO-GO 일 때" 절로 간다.

1. **빈 문서 = `createBlankDocument()`** (번들 `blank2010.hwp`, 구역·단 정의가 든 빈 문단 하나). `createEmpty()` 는 쓰지 않는다(구역·단 정의가 없다, rhwp 주석).
2. **"제목" 스타일은 docbridge 가 더한다.** 빈 문서 템플릿에 "제목"이 없다. `create_document` 가 문서에 "제목"(영문 Title) 문단 스타일이 없으면 `createStyle` + `updateStyleShapes` 로 하나 만든다: 바탕글 기반, 20pt 굵게, 가운데 정렬, 다음 스타일 본문. 양식에 이미 있으면 그것을 쓴다. 사용자가 스타일을 만드는 도구는 여전히 두지 않는다(범위 밖 그대로).
3. **스타일 적용 = `applyStyle` + 스타일 문단 모양으로 `setParaShapeId`.** rhwp `applyStyle` 은 문단에 직접 문단 모양이 있으면 그 모양을 그대로 둬서 개요 스타일을 걸어도 번호가 안 붙는다. 그래서 문단 모양은 스타일 것으로 덮는다(직접 문단 모양은 버린다). 글자는 rhwp 대로: 스타일 글자 모양이던 글자만 새 스타일 글자 모양이 되고, 직접 글자 서식(굵게 등)은 크기까지 그대로 남는다.
4. **개요 여부는 이름이 아니라 스타일 문단 모양(`headType === 'Outline'`)으로 본다.** `list_styles` 의 "개요 번호를 매기는지"도 이것이다. 한컴 공문 양식은 "개요 1"을 번호 없는 모양으로 바꿔 쓰기도 한다(로컬 한컴 기안문). 스타일 종류는 `type === 1` 만 글자 스타일로 본다(한컴 HWP 5 바이너리 일부는 문단 스타일 종류 값이 4·108 로 온다 — 로컬 문서 2개, 하나는 확장자만 `.hwpx`).
5. **표 넣기 = 새 문단 → 바탕글 → `createTable` → rhwp 가 덧붙인 표 아래 빈 문단 지우기 → 칸 채우기 → 머리글.** `createTable` 은 넣는 문단의 문단 모양을 표 문단·모든 칸 문단·표 아래 빈 문단에 물려준다. 개요 문단 뒤에 넣으면 이것들이 모두 개요 번호를 받아 뒤 개요 번호가 "2." 대신 "7." 이 된다(근거 테스트). 새로 생기는 문단은 표가 든 문단 하나다(`ParagraphChanges.inserted` 하나).
6. **열 너비는 rhwp 기본값(쪽 본문 너비 ÷ 열 수)** 을 쓰고 `colWidths` 는 도구에 두지 않는다. `createTableEx` 는 `treatAsChar: true` 일 때만 `colWidths` 를 쓰고, 아니면 `createTable` 과 같다(소스 `create_table_ex_native`). A4 기본 여백에서 41,954 HWPUNIT(≈148mm)을 나눈다.
7. **칸 글자의 줄바꿈은 칸 안 문단으로 나눈다**(`splitParagraphInCell` + `insertTextInCell`). 블록 추출의 칸 text(`\n` 으로 이은 것)와 같은 모양이 된다.
8. **머리글 행 = 한글 "제목 셀"(`setCellProperties({isHeader:true})`) + 표 "제목 줄 자동 반복"(`setTableProperties({repeatHeader:true})`) + 칸 글자 굵게(`applyCharFormatInCell`).** rhwp 에 머리글 속성이 있고 HWPX(`<hp:tc header="1">`, `repeatHeader="1"`)로 저장해 다시 열어도 남는다. 제목 셀 속성만으로는 눈에 띄지 않아 굵은 글자를 같이 건다(docbridge 가 정한 고정 모양 — 사용자가 고르는 직접 서식 도구가 아니다).
9. **양식 본문 비우기** = 구역마다 "남길 문단"(구역 첫 문단 + 머리말·꼬리말·쪽 번호 위치(`head`·`foot`·`pgnp`)가 든 문단) 사이의 이어진 문단을 `deleteRange` 한 번으로 지우고, 남긴 문단에서는 남길 개체 밖의 컨트롤(`deleteControlAt`)과 글자를 지운 뒤 바탕글로 맞춘다. 표·그림·도형·글상자·수식·각주·누름틀·감추기·새 번호 지정은 지운다. 스타일·쪽 설정·머리말·꼬리말 내용은 그대로 남는다.
10. **새 문서의 첫 블록 = 구역 첫 빈 문단을 빈 문단 블록으로 남긴 것**(`extractBlocks` keepEmpty). 빈 문서·비운 양식은 블록이 0개라 `insert_paragraph` 의 기준이 없다. 첫 문단에 id 를 주고, Claude 는 `replace_text` 로 제목을 쓰고 그 뒤로 `insert_paragraph`·`insert_table` 한다(구역 첫 문단 앞에는 넣을 수 없다 — ADR 002).

- **문단마다 `deleteParagraph` 하면 지울 때마다 다시 조판해서 74쪽 문서에서 13.4초**가 걸렸다. 남길 문단 사이를 `deleteRange` 한 번으로 지우면 60ms.
- 머리말·꼬리말은 구역 첫 문단이 아닌 문단에 있을 수 있다(제안요청서 구역 0 은 남긴 문단이 2개). 그 문단을 지우면 머리말이 사라지므로 남긴다.
- `getControls` 는 본문을 목록 0 하나로 보고 문단 번호를 **구역을 이어** 센다(구역마다 다른 목록이 아니다). `blocks.ts` 는 이미 그렇게 읽고, 처음 만든 `bodyControls` 식(구역 정의 순서 = 목록 번호, `delete-blocks.ts`)으로는 여러 구역 문서에서 실패했다(아래 "같이 찾은 것").
- **구역이 여럿이면 구역마다 빈 문단(대개 새 쪽)이 남는다.** 구역을 지우는 공개 API 는 쓰지 않았다(쪽 설정이 구역마다 다르다). 내용은 첫 구역에 쓴다.
- **지운 그림의 바이너리(BinData)는 파일에 남는다.** 제안요청서 양식은 그림을 지워도 HWPX 가 1.8MB(BinData bmp 여러 개, 일부는 머리말 그림일 수 있다). 쓰이지 않는 BinData 를 지우는 공개 API 가 없다. 한글이 쓰이지 않는 BinData 를 문제 삼는지는 한글 확인으로 본다.
- 첫 문단 안에 든 표(`treatAsChar`)·누름틀도 지운다(`본문 첫 문단 안의 표·누름틀도 지운다`).

### HWPX 구조 (한글 확인 파일 8개, 스크래치 검사)

`mimetype` 이 첫 항목·무압축, 모든 XML 이 올바름, header `itemCnt` 가 맞음, `<hp:tc header="1">` 2칸·`repeatHeader="1"`. `charPrIDRef="4294967295"`(−1)는 번호 정의 `paraHead` 의 "글자 모양 없음" 값으로 편집 없는 빈 문서에도 있고 ADR 002 확인 파일(한컴 뷰어에서 경고 없음)에도 있었다. `.hwp` 에서 온 양식(요청서)은 글자 모양에 `borderFillIDRef="0"` 이 있다(rhwp `.hwp` → HWPX 변환 값, ADR 002 확인 파일에는 없던 것 — 한글 확인 대상).

| 질문 | 결론 | 근거 |
|---|---|---|
| `path` 를 필수로 할지 | **필수로 둔다. 절대 경로 또는 `~` 만 받고 상대 경로는 거부한다.** 새 문서에는 원본 폴더가 없어 SPEC-002 의 "상대 경로는 원본 폴더 기준" 을 쓸 수 없고, MCP 서버 cwd 는 사용자가 모른다(#22). 채팅에서는 Claude 가 요청("제안서")으로 이름을 정해 경로를 보여주는 편이 "어디 저장됐지" 를 없앤다. 기본 경로(`~/Downloads/새 문서.hwpx`, 겹치면 번호)는 쓰기 쉽지만 저장 위치가 결과에만 보인다 | 기술 제약(rhwp 와 무관), #22 경로 규칙 |
| 표 머리글 행 표현 | **rhwp 속성(제목 셀 + 제목 줄 반복) + 굵은 글자** | 위 "표 만들기" 머리글 줄. 스타일로 하려면 양식마다 머리글 스타일 이름이 달라(제안요청서 "표-머리", 빈 문서에는 없음) 고를 수 없다 |
| 양식 본문을 비울 때 표·그림 | **지운다.** 남기는 것은 구역·단 정의, 머리말·꼬리말, 쪽 번호 위치. 결과에 지운 개체·남긴 개체 수를 알린다 | 위 "양식 본문 비우기" 표 — 12개 문서 모두 본문 글자 0, 블록 0, 저장 검증 통과 |

## NO-GO 일 때 (한글에서 경고가 나면)

우회해서 GO 로 만들지 않고 결과를 이 ADR 과 스펙에 남긴다.

1. **00-기준(편집 없는 빈 문서)도 경고** → rhwp 빈 문서·HWPX 직렬화 문제. 대안: (a) `.hwp` 로 저장(범위 밖 — 스펙 변경 필요), (b) rhwp 업스트림 이슈, (c) 한컴이 저장한 빈 HWPX 를 docbridge 에 번들해 빈 문서 대신 "양식"으로 연다(라이선스 확인 필요).
2. **01 만 경고, 02(제목 스타일 없이)는 괜찮음** → `createStyle` 로 더한 스타일 문제. 대안: 제목 스타일을 만들지 않고 "차례 제목" 등 있는 스타일을 제목으로 쓰거나, 제목만 바탕글 + 글자 모양(직접 서식 1곳)으로.
3. **표 파일만 경고·표가 깨짐** → 표 아래 빈 문단 지우기를 빼고(rhwp 기본대로 남김) 다시 확인, 다음으로 머리글 속성(제목 셀·반복)을 빼고 확인해 가른다.
4. **양식 파일만 경고** → 비우기 방법(`deleteRange`·`deleteControlAt`) 또는 남은 BinData 문제. 표·그림이 없는 양식(03)과 그림이 있던 양식(06·07)의 결과로 가른다.
5. **개요 번호가 다르게 보임** → 한컴의 개요 번호 계산과 rhwp 가 다른 것. 스타일 문단 모양 덮어쓰기(결정 3)를 다시 본다.

## 같이 찾은 것 (SPEC-002 결함, 이 이슈에서 고치지 않음)

- **`delete_blocks` 가 여러 구역 문서에서 문단째 지우기를 모두 거부한다.** `delete-blocks.ts` `bodyControls` 가 구역마다 본문 목록이 따로 있다고 보고 `secd` 의 `para === 0` 만 세는데, `getControls` 는 본문을 목록 0 하나로 보고 문단 번호를 구역을 이어 센다. 로컬 2구역 문서 2개에서 구역 0 문단을 지워도 "문단에 든 개체를 확인하지 못해 지울 수 없습니다". ADR 002 의 "여러 구역 문서는 fixture 가 없어 확인 못 함" 이 실제로 틀린 경우. 고치는 법: `create-document.ts` `bodyControlsBySection` 처럼 구역 시작 문단 수로 나눈다.
- **`listFields`(edits.ts) 스키마가 글상자 안 하이퍼링크 위치를 받지 못한다.** `getFieldList` 의 `location.path` 가 `{type:"textbox", controlIndex, paraIndex}` 로 오면(로컬 제안요청서) `cellIndex` 가 없어 zod 오류로 `delete_blocks` 가 던진다. 블록 추출(`blocks.ts`)은 다른 스키마라 괜찮다.

## 결과

- 쉬워지는 것: #36 은 `createBlankDocument`·`clearTemplateBody`·`ensureTitleStyle` 을 뷰어 요청(`create_document`)으로 감싸고 첫 문단을 빈 문단 블록으로 남긴다. #37 은 `paragraphStyles`·`styleIdByName`·`applyParagraphStyle` 을 편집 종류(`set_style`, `insert_paragraph` 의 `style`)로, #38 은 `insertTableParagraph` 를 편집 종류(`insert_table`, `ParagraphChanges.inserted` 하나)로 더한다.
- 어려워지는 것: rhwp 의 `applyStyle`·`createTable` 의미가 바뀌면 보정이 틀어진다. `(근거)` 테스트가 지금 동작을 고정한다.
- 다시 볼 조건: 사용자 한글 확인 결과(위 NO-GO 절), rhwp 가 쓰이지 않는 BinData 정리·구역 지우기 API 를 내면 양식 비우기를 다시 본다. `colWidths` 가 필요해지면 `setCellProperties({width})` 를 확인한다.
- 확인 못 한 것: 한글 프로그램에서 열기(사용자), 정식 한글(편집기)에서 제목 셀·제목 줄 반복이 쪽을 넘길 때 반복되는지(확인 파일의 표는 한 쪽), 브라우저 뷰어에서의 렌더링(Node 로만 확인 — 같은 WASM), 영문 판 한글에서의 스타일 이름("Outline 1" 등 — 영문 이름도 받게 해 두었다).
