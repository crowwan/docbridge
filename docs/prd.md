# docbridge PRD

## 한 줄 정의

받은 한글(HWP/HWPX) 문서를 **내가 쓰는 Claude 채팅**에서 묻고 말로 고치게 해 주는 로컬 브리지. 문서는 브라우저 뷰어에 원래 모양대로 띄워 두고, Claude 가 고친 내용과 답의 근거가 그 화면에 바로 보인다.

## 사용자와 상황

- **1차 사용자: 나.** 한글 문서를 받으면 "회신 기한이 언제야?", "3번 항목을 1번 위로 올려줘" 같은 일을 하고 싶었는데, 한컴을 직접 조작하거나 예전 COM 방식 MCP(`hwp-mcp-advanced-custom`)로는 잘 안 됐다.
- **넓히면: 한글을 가끔 받아서 보고 조금 고치는 비개발자.** 맥·크롬북 사용자, 한컴을 설치하기 싫은 사람, 받은 공문·공고·신청서를 고쳐서 돌려보내는 사람. rhwp 크롬 확장(주간 사용자 약 20만)의 리뷰·이슈에서 확인한 사용 흐름이 "받아서 열기 → 조금 고치기 → 다시 보내기"다 (`docs/research/rhwp-issues-analysis.md`).
- 공무원 업무망 사용자는 기관 AI 정책 때문에 1차 대상이 아니다.

장면: Claude Desktop(또는 Cowork·Code)에서 "이 파일 열어줘" → 브라우저에 문서가 뜬다 → 채팅으로 묻고 시킨다 → 화면에서 결과를 보고 → HWPX 로 저장해 한글에서 연다.

## 핵심 경험

1. **묻기**: 문서 내용을 물으면 답과 함께 **근거 위치가 뷰어에서 하이라이트**된다.
2. **말로 고치기**: 문단 이동·바꾸기·표 칸 채우기를 채팅 한 마디로 한다. 서식과 자동 번호가 유지되고, 한 번에 되돌릴 수 있다.
3. **한글에서 그대로 열리는 저장**: 저장한 파일이 한글에서 손상·변조 경고 없이 열린다. 저장 전에 검증한다.

## 범위

### 하는 것

- 로컬 MCP 서버(stdio)로 Claude Desktop·Cowork·Code 에 연결
- 브라우저 뷰어에 HWP/HWPX 열기, 렌더링, 근거 하이라이트
- 블록 단위 도구: 문서 구조 보기, 찾기, 문단 이동·삽입·삭제, 텍스트 바꾸기, 표 칸 채우기, 하이라이트, 되돌리기, 저장
- HWPX 로 저장 + 저장 전 검증
- 사람이 뷰어에서 직접 고친 내용도 Claude 가 다시 읽을 수 있게 반영

### 하지 않는 것

- 앱 안 AI 패널, API 키 입력 (AI 는 사용자의 Claude 채팅이 맡는다. rhwp PR #8170 의 AI 패널과 겹치지 않게)
- 서식·개체 삽입 전반(그림·도형·수식 새로 넣기, 표 테두리 등) — 이건 rhwp 에디터의 영역
- `.hwp`(바이너리)로 저장 — 저장은 HWPX
- claude.ai 웹·모바일용 원격 커넥터 (문서가 서버를 거치게 됨)
- 엑셀·PPT. 도구 이름은 포맷과 무관하게 짓고 한글 처리는 rhwp 어댑터로 분리해 둔다
- rhwp 포크·업스트림 기여 (공개 API 로 해결하고, rhwp 버그로 막힐 때만 이슈)

## 데이터 모델 (개요)

- **문서 세션**: 브라우저에 열린 문서 하나. rhwp `HwpDocument` 핸들, 원본 파일 이름, 스냅샷 스택. 문서 상태의 단일 기준은 브라우저다.
- **블록**: Claude 에게 보여주는 단위. `id`(우리가 부여하는 안정 ID — 문단을 넣고 지워도 바뀌지 않음), `kind`(문단/표/칸/누름틀), 현재 위치(구역·문단 인덱스, 표 좌표), 텍스트, 문맥 해시, 번호 정보(자동 번호인지).
- **편집 명령**: `move` / `insert` / `delete` / `replace` / `setCell` / `highlight` / `undo` / `save`. 대상은 블록 ID + 문맥 해시로 지정하고, 해시가 다르면 거부한다.
- **하이라이트**: 블록 ID 또는 텍스트 범위 → rhwp 범위 좌표 → 뷰어 오버레이.

## 기술 스택

- TypeScript 전체. Node 24 (`.nvmrc`)
- MCP 서버: 공식 MCP TypeScript SDK, stdio
- 서버 ↔ 뷰어: 127.0.0.1 WebSocket + 세션 토큰. 뷰어 페이지는 MCP 서버가 직접 제공한다 (SPEC-001)
- 뷰어: Vite + `@rhwp/core`(WASM, MIT) 직접 사용, 0.8.7 고정. `@rhwp/editor` 는 붙이지 않는다 (ADR 001)
- 테스트: Vitest(1~2 계층), Playwright(뷰어 스모크)
- 배포(v0.2): Claude Desktop 확장(.mcpb)

결정 이유: `docs/decisions/001-stack-and-rhwp.md` (SPEC-001 기술 검증).
