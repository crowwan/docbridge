# SPEC-005 여러 자리 한 번에 바꾸기

## 배경과 목표

SPEC-002 의 `replace_text` 는 한 번에 한 자리(블록 하나·칸 하나)만 바꾼다. 실제 공고문에서 "24년을 26년으로 고쳐줘" 라고 하자(2026-10-27, v0.1.0 QA), Claude 는 `find_text` 로 찾은 자리마다 `replace_text` 를 따로 불렀다. 그래서:

- 초록 바뀐 블록 표시가 편집마다 지워지고 새로 그려져, 끝나면 마지막 한 자리만 보인다.
- "되돌려" 하면 마지막 한 자리만 돌아간다. 사람에게는 편집 하나인데 docbridge 에는 n 개다.
- 앞 자리를 바꾸면 같은 블록 뒤 자리 위치가 밀려 Claude 가 다시 찾아야 한다(호출이 늘고, 틀린 위치로 바꿀 위험).

이 스펙이 끝나면 "A 를 B 로 다 바꿔줘" 는 도구 한 번, 되돌리기 한 번이고, 바뀐 자리가 모두 초록으로 남는다. "이 문단들의 A 만" 처럼 골라 바꾸기도 한 편집으로 된다.

## 동작 정의

### MCP 도구

| 도구 | 입력 | 결과 |
|---|---|---|
| `replace_all` (새) | `find`(필수, 찾을 글자 — `find_text` 와 같은 규칙: 대소문자·띄어쓰기 그대로), `text`(바꿀 글자, 빈 글자면 지우기, 줄바꿈 없이), `ids`(선택: 이 블록들 안에서만) | 문단·표 칸에서 `find` 를 모두 찾아 `text` 로 바꾼다. 편집 하나(undo 한 번). 결과 `{ replaced, changed: [{ id, cell?, text }], warnings? }` — `replaced` 는 바꾼 자리 수, `changed` 는 바뀐 블록(칸) |
| `replace_text` (확장) | 기존 `target` 대신 `targets`(1개 이상, 같은 `TextTarget` 배열)도 받는다. `target`·`targets` 중 하나만 | 준 자리를 모두 바꾼다. 편집 하나(undo 한 번). 위치는 모두 **편집 전 문서 기준**이다(앞 자리를 바꿔 뒤가 밀려도 docbridge 가 맞춘다). 결과 모양은 기존과 같다 |

- 찾는 범위는 `find_text` 와 같다: 본문 문단과 표 칸. 누름틀 값·머리말·꼬리말·각주는 바꾸지 않는다.
- 일치가 0개면 편집하지 않고 오류: "'<find>' 를 찾지 못했습니다." (undo 칸을 쓰지 않는다)
- `targets` 끼리 겹치면(같은 블록·칸에서 범위가 겹침) 아무것도 바꾸지 않고 오류: "바꿀 자리가 겹칩니다: <id> <start>~<end>".
- `targets` 중 하나라도 잘못되면(없는 id·칸·범위 밖) 아무것도 바꾸지 않는다 — 일부만 바뀐 문서를 남기지 않는다.
- 글자 모양 규칙은 `replace_text` 와 같다: 자리마다 바뀌는 자리 첫 글자의 글자 모양을 따른다.
- `find` 가 `text` 의 일부여서(예: "24" → "2024") 다시 찾으면 또 걸리는 경우도, 찾기는 편집 전 문서에서 한 번만 하므로 한 번씩만 바뀐다.

### 바뀐 블록 표시

- 한 편집으로 바뀐 블록은 **모두** 초록 테두리가 남는다(기존 공용 경로가 이미 블록 목록을 받으므로 표시 규칙은 그대로, 여러 블록이 오는 것뿐).
- 표시는 지금처럼 다음 편집에서 지워진다. 편집 사이에 쌓는 것은 이 스펙 밖(아래).

### 크기

- 한 번에 바꾸는 자리는 500 곳까지. 넘으면 바꾸지 않고 오류: "바꿀 자리가 <n> 곳이라 너무 많습니다(500 까지). ids 로 범위를 나눠 주세요."

## 수용 기준

- [ ] AC-1 `replace_all` 이 문단·표 칸의 모든 일치를 바꾸고, `undo` 한 번에 모두 돌아간다 (자동)
- [ ] AC-2 `replace_all` 의 `ids` 를 주면 그 블록 안 일치만 바뀐다 (자동)
- [ ] AC-3 일치가 0개면 오류이고 문서·undo 칸이 그대로다 (자동)
- [ ] AC-4 `replace_text` 의 `targets` 가 같은 블록 안 여러 자리를 편집 전 위치 기준으로 맞게 바꾼다(앞 자리 길이가 달라져도) (자동)
- [ ] AC-5 `targets` 가 겹치거나 하나라도 잘못되면 아무것도 바뀌지 않는다 (자동)
- [ ] AC-6 자리마다 글자 모양이 그 자리 첫 글자 모양을 따른다(굵은 자리와 보통 자리가 섞인 문서) (자동)
- [ ] AC-7 한 편집으로 바뀐 블록이 모두 뷰어에 초록 테두리로 남는다 (자동 — E2E)
- [ ] AC-8 500 곳을 넘으면 오류이고 바뀌지 않는다 (자동)
- [ ] AC-9 실제 공고문에서 "24년을 26년으로 다 바꿔줘" 가 도구 한 번으로 끝나고, 저장한 파일이 한글에서 열린다 (수동 QA)

## 범위 밖

- 정규식·대소문자 무시 찾기
- 누름틀 값·머리말·꼬리말·각주 바꾸기
- 편집 사이에 초록 표시 쌓기(저장할 때까지 바뀐 곳 모두 보기) — ①·② 를 써 본 뒤 결정
- 서식 바꾸기(글자 모양을 함께 바꾸는 찾아 바꾸기)

## 기술 메모

- 새 편집 종류는 `src/core/edit-operations.ts` 의 kind 판별 유니언에 스키마 + `applyEdit` case 하나(CLAUDE.md 규칙). `replace_all` 은 서버가 열린 블록으로 일치를 계산해 `targets` 로 바꾼 뒤 같은 편집(`replace_text` 여러 자리)으로 보내면, 뷰어 쪽 편집은 하나만 늘면 된다.
- 같은 문단 안 여러 자리는 **뒤에서부터** 바꾸면 앞 위치가 밀리지 않는다. 블록·칸 단위로 묶어 위치 내림차순으로 적용한다.
- 스냅샷·depth 대조·바뀐 블록 계산은 `document-editor.ts` 공용 경로를 그대로 탄다.
- `find_text` 의 일치 계산(`src/core/find-text.ts` findInBlocks)을 재사용한다.
