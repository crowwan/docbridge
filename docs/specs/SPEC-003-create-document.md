# SPEC-003 새 문서 만들기

## 배경과 목표

SPEC-001·002 로 받은 문서를 열고 묻고 고치고 저장할 수 있다. 하지만 "제안서 초안 하나 만들어줘" 처럼 **처음부터 한글 문서를 만드는 일**은 docbridge 로 할 수 없다.

실제로 Claude Cowork 에서 제안서를 만들어 달라고 했을 때, Claude 는 VM 에 python-hwpx 를 설치해 HWPX 를 따로 만든 뒤 docbridge 로 열어 확인·하이라이트만 했다(2026-10-27). 그리고 스스로 "create_document 가 있으면 생성부터 편집까지 한 도구 안에서 끝낼 수 있다"고 제안했다. 이 방식은 셸이 있는 Claude Code·Cowork 에서만 되고, 셸이 없는 Claude Desktop 채팅에서는 막힌다. 외부 라이브러리로 만든 파일은 한컴 호환을 docbridge 가 보장하지도 못한다.

이 스펙이 끝나면:
- 채팅에서 "제안서 초안 만들어줘" 라고 하면 docbridge 가 빈 문서(또는 고른 양식)를 뷰어에 띄우고, Claude 가 제목·개요·본문·표를 채운다.
- 결과는 SPEC-002 의 저장·검증 규칙 그대로 HWPX 로 저장되고 한글에서 열린다.
- 셸 없는 Claude Desktop 에서도 된다.

## 동작 정의

### 원칙

- **기존 편집 도구를 그대로 쓴다.** 새 문서도 "열린 문서"다. 채우기는 SPEC-002 의 `insert_paragraph`·`replace_text`·`delete_blocks`·`move_blocks`·`undo` 로 한다. 새로 더하는 도구는 시작(`create_document`)과 그 도구들로 안 되는 것(표 만들기, 스타일 고르기)뿐이다.
- **서식은 스타일로만.** 글자 크기·굵기·색을 하나하나 정하는 도구는 두지 않는다. 문서의 스타일("제목", "개요 1", "본문" 등)을 골라 쓴다. 한글 문서에서 보통 쓰는 방식이고, 개요 번호도 스타일이 매긴다.
- **한컴 호환은 rhwp 가 만든 문서로.** 빈 문서는 rhwp 에 들어 있는 한컴 빈 문서 템플릿(`createBlankDocument`)에서 시작한다. 외부 라이브러리(python-hwpx 등)는 쓰지 않는다.

### MCP 도구

| 도구 | 입력 | 결과 |
|---|---|---|
| `create_document` | `path`(저장할 경로), `template`(선택: 양식으로 쓸 `.hwp`/`.hwpx` 파일 경로), `keep_content`(선택, 기본 false) | 새 문서를 뷰어에 띄운다. `template` 이 없으면 빈 문서, 있으면 그 파일의 스타일·쪽 설정·머리말 등을 그대로 쓰고 본문은 비운다(`keep_content: true` 면 본문도 남김). 결과: 저장 경로, 쪽 수, 블록 수, 쓸 수 있는 스타일 목록 |
| `list_styles` | 없음 | 지금 문서의 스타일 이름 목록(문단 스타일만), 각 스타일이 개요 번호를 매기는지 |
| `insert_paragraph` (확장) | 기존 입력 + `style`(선택, 스타일 이름) | 새 문단에 그 스타일을 적용한다. 없으면 SPEC-002 규칙대로 기준 문단 모양 |
| `set_style` | `ids`(문단 블록), `style` | 문단 스타일을 바꾼다 |
| `insert_table` | `before` 또는 `after`(블록 id), `rows`, `cols`, `cells`(선택, 행×열 글자 배열), `header`(선택, 첫 행을 머리글로) | 기준 블록 앞/뒤에 새 문단을 만들고 표를 넣는다. 결과: 새 표 블록 id, 칸 수 |

`create_document` 는 저장하지 않은 편집이 있는 문서를 대신한다(SPEC-002 "새 문서를 열면" 규칙 — 버린 편집 수 알림).

### 새 문서와 저장

- 새 문서는 **아직 파일이 없다.** `path` 는 처음 저장할 자리다. 이미 파일이 있으면 `create_document` 단계에서 거부한다("이미 있는 파일입니다 … 다른 경로를 주세요").
- `save_document` 를 경로 없이 부르면 `path` 에 저장한다(배타 생성, SPEC-002). 저장하면 그 파일이 "마지막 파일"이 된다.
- 한 번도 저장하지 않은 새 문서는 새로고침하면 사라진다. 뷰어는 확인 창을 띄우고, 다음 도구 결과에 "저장하지 않은 새 문서가 사라졌습니다" 를 알린다(SPEC-002 AC-14 와 같은 방식).
- `template` 파일은 읽기만 한다. 양식 파일을 덮어쓰지 않는다.

### 기본 흐름

1. "DocBridge 도입 제안서 초안을 ~/Downloads/제안서.hwpx 로 만들어줘"
2. Claude 가 `create_document(path)` → 뷰어에 빈 A4 문서가 뜨고, 스타일 목록이 돌아온다.
3. Claude 가 `insert_paragraph(…, style: "제목")`, `insert_paragraph(…, style: "개요 1")`, 본문 문단들, `insert_table(after, 3, 2, cells, header)` 로 채운다. 뷰어에 바뀐 블록 표시가 남는다.
4. 사용자가 "2장이랑 3장 순서 바꿔줘" → `move_blocks`.
5. "저장해줘" → `save_document()` → `~/Downloads/제안서.hwpx`.
6. 한글에서 연다.

### 예외와 경계 상황

- **없는 스타일**: "없는 스타일입니다: <이름>. list_styles 로 목록을 보세요."
- **양식 파일을 못 읽음**: SPEC-001 열기 오류 문구 그대로(형식·없음·크기·rhwp 이유).
- **양식 본문 비우기**: 본문을 비울 때 구역 첫 문단(구역·단 정의)은 남기고 글자만 지운다. 비울 수 없는 개체(머리말·꼬리말은 남김, 본문 안 그림·표·글상자는 지움)를 결과에 알린다.
- **표 크기**: `rows`·`cols` 는 1~50. `cells` 크기가 `rows`×`cols` 와 다르면 거부. 칸 글자에 줄바꿈이 있으면 칸 안 문단으로 나눈다(`replace_text` 와 다름 — 표 칸은 여러 문단이 흔하다).
- **표 칸 안에 표**: 만들지 않는다.
- **스타일 바꾸기 대상**: 문단 블록만. 표·누름틀 블록이면 거부.

## 수용 기준

- [ ] AC-1 `create_document` 는 빈 문서를 뷰어에 띄우고 저장 경로·쪽 수·블록 수·스타일 목록을 돌려준다. `path` 에 파일이 이미 있으면 거부한다 (자동)
- [ ] AC-2 `template` 을 주면 그 파일의 스타일·쪽 설정을 쓰고 본문은 비운 새 문서가 되며, 양식 파일은 바뀌지 않는다. `keep_content: true` 면 본문이 남는다 (자동)
- [ ] AC-3 `list_styles` 는 문단 스타일 이름과 개요 번호 여부를 돌려준다 (자동)
- [ ] AC-4 `insert_paragraph` 에 `style` 을 주면 그 스타일이 적용되고, 개요 스타일 문단은 번호가 매겨진다. 없는 스타일은 거부한다 (자동)
- [ ] AC-5 `set_style` 은 문단 블록의 스타일을 바꾸고, 표·누름틀 블록은 거부한다 (자동)
- [ ] AC-6 `insert_table` 은 기준 블록 앞/뒤에 `rows`×`cols` 표를 만들고 `cells` 글자를 채우며 새 표 블록 id 를 준다. 크기가 틀린 `cells` 는 거부한다 (자동)
- [ ] AC-7 새 문서를 `save_document` 로 경로 없이 저장하면 `path` 에 저장되고, 다시 `open_document` 하면 내용이 그대로다 (자동)
- [ ] AC-8 한 번도 저장하지 않은 새 문서를 새로고침하면 사라졌다고 알린다 (자동)
- [ ] AC-9 새 문서를 만들고 편집 도구(undo 포함)가 SPEC-002 와 같이 동작한다 (자동)
- [ ] AC-10 빈 문서·양식에서 만든 문서(제목·개요·본문·표)를 저장한 파일이 한글 프로그램에서 경고 없이 열리고 스타일·개요 번호·표가 맞다 (수동 QA)

## 기술 검증 (첫 이슈)

- `createBlankDocument()` 로 만든 문서: 스타일 목록(`getStyleList`)에 "제목"·"개요 1~7"·"본문" 등이 있는지, 개요 번호가 매겨지는지, HWPX 로 저장해 한글에서 열리는지.
- `applyStyle` 로 문단 스타일 적용 — 문단·글자 모양이 스타일대로 바뀌는지, 직접 서식과 섞일 때.
- `createTable`/`createTableEx` + 칸 글자 넣기: 표 너비(`colWidths`), 머리글 행 표현 방법(rhwp 에 머리글 행 속성이 있는지, 없으면 스타일·글자 모양으로), 칸 안 여러 문단.
- 양식 파일 본문 비우기: 구역 첫 문단 남기기, 본문 개체 지우기(SPEC-002 delete 규칙 재사용 가능 여부).
- 비교 기준: python-hwpx 로 만든 `~/Downloads/DocBridge_도입제안서_v0.1.hwpx` 가 한글에서 어떻게 보이는지(사용자 확인)와 rhwp 로 같은 내용을 만든 결과.

GO 기준: 빈 문서와 양식 문서 각각으로 제목·개요·본문·표가 든 문서를 만들어 한글에서 경고 없이 열리고 개요 번호·표가 맞다.

## 범위 밖

- 글자 크기·굵기·색·정렬 같은 직접 서식, 표 테두리·칸 배경색 직접 지정
- 새 스타일 만들기
- 그림·도형·수식·차트 넣기
- 머리말·꼬리말·쪽 번호 만들기·고치기(양식에 있는 것은 그대로 씀)
- 표 행·열 추가·삭제, 칸 병합 (다음 스펙 후보)
- 여러 문서 동시 열기(새 문서를 만들면 열린 문서를 대신한다)
- `.hwp` 로 저장

## 기술 메모

- rhwp 0.8.7 API: `createBlankDocument()`(번들 `blank2010.hwp`, 한글 호환), `HwpDocument.createEmpty()`(구역·단 정의 없음 — 한글 호환이 필요하면 쓰지 않는다고 rhwp 주석이 밝힘), `getStyleList`, `applyStyle(sec, para, styleId)`, `createTable`/`createTableEx({sectionIdx, paraIdx, charOffset, rowCount, colCount, treatAsChar?, colWidths?})`, `insertTableRow`/`insertTableColumn`(범위 밖이지만 있음).
- 새 도구는 SPEC-002 편집 공용 경로(스냅샷·depth 대조·바뀐 블록 표시·`ParagraphChanges`)에 편집 종류로 더한다. `insert_table` 은 "문단 넣기 + 표 넣기" 한 편집.
- 새 문서의 "원본"은 없다. 세션의 `sourcePath` 가 비어 있을 때 저장 규칙(원본 덮어쓰기 판정)을 건너뛰고 `path` 를 기본 경로로 쓴다.

## 열린 질문

- `path` 를 필수로 할지(지금 안), 없으면 `~/Downloads/새 문서.hwpx`(겹치면 번호)로 할지 — 결정: 기술 검증 후 (첫 이슈)
- 표 머리글 행을 어떻게 표현할지(rhwp 속성 / 스타일 / 굵은 글자 모양) — 결정: 기술 검증 후 (첫 이슈)
- 양식 본문을 비울 때 표·그림을 지울지 남길지(지금 안: 지움) — 결정: 기술 검증 후 (첫 이슈)
- 스타일 이름이 한글 판·영문 판에서 다를 때(예: "개요 1" / "Outline 1") 영문 이름도 받을지 — 결정: 구현 중
