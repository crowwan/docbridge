# SPEC-003 새 문서 만들기

## 배경과 목표

SPEC-001·002 로 받은 문서를 열고 묻고 고치고 저장할 수 있다. 하지만 "제안서 초안 하나 만들어줘" 처럼 **처음부터 한글 문서를 만드는 일**은 docbridge 로 할 수 없다.

실제로 Claude Cowork 에서 제안서를 만들어 달라고 했을 때, Claude 는 VM 에 python-hwpx 를 설치해 HWPX 를 따로 만든 뒤 docbridge 로 열어 확인·하이라이트만 했다(2026-10-27). 그리고 스스로 "create_document 가 있으면 생성부터 편집까지 한 도구 안에서 끝낼 수 있다"고 제안했다. 이 방식은 셸이 있는 Claude Code·Cowork 에서만 되고, 셸이 없는 Claude Desktop 채팅에서는 막힌다. 외부 라이브러리로 만든 파일은 한컴 호환을 docbridge 가 보장하지도 못한다.

이 스펙이 끝나면:
- 채팅에서 "제안서 초안 만들어줘" 라고 하면 docbridge 가 빈 문서(또는 고른 양식)를 뷰어에 띄우고, Claude 가 제목·개요·본문·표를 채운다.
- 결과는 SPEC-002 의 저장·검증 규칙 그대로 HWPX 로 저장되고 한글에서 열린다.
- 셸 없는 Claude Desktop 에서도 된다.

## 동작 정의

### 원칙

- **기존 편집 도구를 그대로 쓴다.** 새 문서도 "열린 문서"다. 채우기는 SPEC-002 의 `insert_paragraph`·`replace_text`·`delete_blocks`·`move_blocks`·`undo` 로 한다. 새로 더하는 도구는 시작(`create_document`)과 그 도구들로 안 되는 것(표 만들기, 스타일 고르기)뿐이다.
- **서식은 스타일로만.** 글자 크기·굵기·색을 하나하나 정하는 도구는 두지 않는다. 문서의 스타일("제목", "개요 1", "본문" 등)을 골라 쓴다. 한글 문서에서 보통 쓰는 방식이고, 개요 번호도 스타일이 매긴다. 예외는 docbridge 가 정한 고정 모양 두 가지뿐이다: 새 문서에 더하는 "제목" 스타일, 표 머리글 행의 굵은 글자(아래).
- **한컴 호환은 rhwp 가 만든 문서로.** 빈 문서는 rhwp 에 들어 있는 한컴 빈 문서 템플릿(`createBlankDocument`)에서 시작한다. 외부 라이브러리(python-hwpx 등)는 쓰지 않는다.

### MCP 도구

| 도구 | 입력 | 결과 |
|---|---|---|
| `create_document` | `path`(필수, 저장할 경로 — 절대 경로 또는 `~`), `template`(선택: 양식으로 쓸 `.hwp`/`.hwpx` 파일 경로), `keep_content`(선택, 기본 false) | 새 문서를 뷰어에 띄운다. `template` 이 없으면 빈 문서, 있으면 그 파일의 스타일·쪽 설정·머리말 등을 그대로 쓰고 본문은 비운다(`keep_content: true` 면 본문도 남김). 결과: 저장 경로, 쪽 수, 블록 수, **첫 블록 id**(아래 "새 문서의 첫 블록"), 쓸 수 있는 스타일 목록, 양식이면 지운 개체·남긴 개체 수 |
| `list_styles` | 없음 | 지금 문서의 문단 스타일 목록(이름·영문 이름), 각 스타일이 개요 번호를 매기는지(이름이 아니라 스타일의 문단 모양으로 판단 — 양식에 따라 "개요 1" 도 번호가 없을 수 있다) |
| `insert_paragraph` (확장) | 기존 입력 + `style`(선택, 스타일 이름) | 새 문단에 그 스타일을 적용한다(아래 "스타일 적용"). 없으면 SPEC-002 규칙대로 기준 문단 모양 |
| `set_style` | `ids`(문단 블록), `style` | 문단 스타일을 바꾼다(아래 "스타일 적용") |
| `insert_table` | `before` 또는 `after`(블록 id), `rows`, `cols`, `cells`(선택, 행×열 글자 배열), `header`(선택, 첫 행을 머리글로) | 기준 블록 앞/뒤에 새 문단(바탕글 문단·글자 모양 — 앞 문단의 직접 서식을 물려받지 않는다) 하나를 만들고 표를 넣는다. 열 너비는 쪽 본문 너비를 열 수로 똑같이 나눈다. 결과: 새 표 블록 id, 칸 수 |

스타일 이름은 한글 이름과 영문 이름(예: "개요 1" / "Outline 1") 둘 다 받는다.

`create_document` 는 저장하지 않은 편집이 있는 문서를 대신한다(SPEC-002 "새 문서를 열면" 규칙 — 버린 편집 수 알림).

### 새 문서의 스타일·첫 블록

- **"제목" 스타일**: rhwp 빈 문서 템플릿에는 "제목" 스타일이 없다(바탕글·본문·개요 1~10·머리말·각주·미주·메모·차례 제목·차례 1~3·캡션). `create_document` 는 문서에 "제목" 또는 영문 이름 Title 인 문단 스타일이 없으면 하나 더한다: 바탕글 기반, 20pt 굵게, 가운데 정렬, 다음 스타일 본문. 양식에 이미 있으면 그것을 쓴다.
- **새 문서의 첫 블록**: 빈 문서와 비운 양식은 글자가 없어 블록이 0개다. 구역 첫 문단(구역·단 정의가 든 빈 문단)을 빈 문단 블록으로 남겨 id 를 준다(SPEC-002 "편집으로 비운 문단"과 같은 방식). Claude 는 이 블록을 `replace_text` 로 채우고(보통 제목) 그 뒤로 `insert_paragraph`·`insert_table` 한다. 구역 첫 문단 앞에는 넣을 수 없다(SPEC-002).
- **스타일 적용**(`insert_paragraph` 의 `style`, `set_style`): 문단 모양은 스타일 것으로 바꾼다(정렬·들여쓰기 같은 직접 문단 모양은 없어진다 — 그래야 개요 번호가 붙는다). 글자는 스타일 글자 모양이던 글자만 새 스타일 글자 모양이 되고, 직접 글자 서식(굵게 등)은 크기까지 그대로 남는다.
- **표 머리글 행**(`header: true`): 첫 행 칸을 한글 "제목 셀"로, 표를 "제목 줄 자동 반복"으로 하고(표가 쪽을 넘기면 첫 행이 다시 나온다) 첫 행 글자를 굵게 한다.

### 새 문서와 저장

- 새 문서는 **아직 파일이 없다.** `path` 는 처음 저장할 자리다. 이미 파일이 있으면 `create_document` 단계에서 거부한다("이미 있는 파일입니다 … 다른 경로를 주세요").
- `path` 는 절대 경로나 `~` 로 시작해야 한다. 상대 경로는 거부한다(새 문서에는 SPEC-002 의 기준인 원본 폴더가 없고, MCP 서버 작업 폴더는 사용자가 모른다): "새 문서 경로는 절대 경로나 ~ 로 주세요(예: ~/Downloads/제안서.hwpx)". 확장자 규칙은 SPEC-002 저장과 같다(없으면 `.hwpx`, 다른 확장자 거부).
- `save_document` 를 경로 없이 부르면 `path` 에 저장한다(배타 생성, SPEC-002). 저장하면 그 파일이 "마지막 파일"이 된다.
- 한 번도 저장하지 않은 새 문서는 새로고침하면 사라진다. 뷰어는 확인 창을 띄우고, 다음 도구 결과에 "저장하지 않은 새 문서가 사라졌습니다" 를 알린다(SPEC-002 AC-14 와 같은 방식).
- `template` 파일은 읽기만 한다. 양식 파일을 덮어쓰지 않는다.

### 기본 흐름

1. "DocBridge 도입 제안서 초안을 ~/Downloads/제안서.hwpx 로 만들어줘"
2. Claude 가 `create_document(path)` → 뷰어에 빈 A4 문서가 뜨고, 첫 블록 id 와 스타일 목록이 돌아온다.
3. Claude 가 `replace_text(첫 블록, "DocBridge 도입 제안서")` + `set_style([첫 블록], "제목")`, 그 뒤로 `insert_paragraph(…, style: "개요 1")`, 본문 문단들, `insert_table(after, 3, 2, cells, header)` 로 채운다. 뷰어에 바뀐 블록 표시가 남는다.
4. 사용자가 "2장이랑 3장 순서 바꿔줘" → `move_blocks`.
5. "저장해줘" → `save_document()` → `~/Downloads/제안서.hwpx`.
6. 한글에서 연다.

### 예외와 경계 상황

- **없는 스타일**: "없는 스타일입니다: <이름>. list_styles 로 목록을 보세요."
- **양식 파일을 못 읽음**: SPEC-001 열기 오류 문구 그대로(형식·없음·크기·rhwp 이유).
- **양식 본문 비우기**: 구역 첫 문단(구역·단 정의)과 머리말·꼬리말·쪽 번호 위치가 든 문단은 남기고, 그 문단의 글자와 다른 개체를 지운 뒤 바탕글 문단 모양·글자 모양으로 맞춘다(양식 첫 문단의 큰 글씨 등은 남지 않는다). 그 밖의 문단은 통째로 지운다. 본문 안 표·그림·도형·글상자·수식·각주·누름틀은 지우고, 결과에 지운 개체와 남긴 개체(머리말·꼬리말 등)를 이름별 수로 알린다.
- **구역이 여럿인 양식**: 구역마다 남긴 빈 문단이 남는다(구역이 새 쪽에서 시작하면 빈 쪽). 첫 블록은 첫 구역 첫 문단이다.
- **지운 그림의 바이너리**: 양식에서 지운 그림 데이터가 파일에 남아 크기가 줄지 않을 수 있다(rhwp 에 정리 API 가 없다).
- **표 크기**: `rows`·`cols` 는 1~50. `cells` 크기가 `rows`×`cols` 와 다르면 거부. 칸 글자에 줄바꿈이 있으면 칸 안 문단으로 나눈다(`replace_text` 와 다름 — 표 칸은 여러 문단이 흔하다).
- **표 칸 안에 표**: 만들지 않는다.
- **스타일 바꾸기 대상**: 문단 블록만. 표·누름틀 블록이면 거부. 글자 스타일("쪽 번호" 등)은 목록에 없고 받지 않는다.

## 수용 기준

- [ ] AC-1 `create_document` 는 빈 문서를 뷰어에 띄우고 저장 경로·쪽 수·블록 수·첫 블록 id·스타일 목록("제목" 포함)을 돌려준다. `path` 에 파일이 이미 있거나 상대 경로면 거부한다 (자동)
- [ ] AC-2 `template` 을 주면 그 파일의 스타일·쪽 설정·머리말·꼬리말을 쓰고 본문(표·그림 포함)은 비운 새 문서가 되며, 지운 개체·남긴 개체를 알리고, 양식 파일은 바뀌지 않는다. `keep_content: true` 면 본문이 남는다 (자동)
- [ ] AC-3 `list_styles` 는 문단 스타일 이름과 개요 번호 여부를 돌려준다 (자동)
- [ ] AC-4 `insert_paragraph` 에 `style` 을 주면 그 스타일이 적용되고(기준 문단에 직접 문단 모양이 있어도), 개요 스타일 문단은 번호가 매겨진다. 없는 스타일은 거부한다 (자동)
- [ ] AC-5 `set_style` 은 문단 블록의 스타일을 바꾸고, 표·누름틀 블록은 거부한다 (자동)
- [ ] AC-6 `insert_table` 은 기준 블록 앞/뒤에 `rows`×`cols` 표를 만들고 `cells` 글자를 채우며 새 표 블록 id 를 준다. 개요 문단 뒤에 넣어도 표와 뒤 문단의 개요 번호가 밀리지 않는다. `header` 면 첫 행이 제목 셀·제목 줄 반복·굵은 글자다. 크기가 틀린 `cells` 는 거부한다 (자동)
- [ ] AC-7 새 문서를 `save_document` 로 경로 없이 저장하면 `path` 에 저장되고, 다시 `open_document` 하면 내용이 그대로다 (자동)
- [ ] AC-8 한 번도 저장하지 않은 새 문서를 새로고침하면 사라졌다고 알린다 (자동)
- [ ] AC-9 새 문서를 만들고 편집 도구(undo 포함)가 SPEC-002 와 같이 동작한다 (자동)
- [ ] AC-10 빈 문서·양식에서 만든 문서(제목·개요·본문·표)를 저장한 파일이 한글 프로그램에서 경고 없이 열리고 스타일·개요 번호·표가 맞다 (수동 QA)

## 기술 검증 (첫 이슈)

- `createBlankDocument()` 로 만든 문서: 스타일 목록(`getStyleList`)에 "제목"·"개요 1~7"·"본문" 등이 있는지, 개요 번호가 매겨지는지, HWPX 로 저장해 한글에서 열리는지.
- `applyStyle` 로 문단 스타일 적용 — 문단·글자 모양이 스타일대로 바뀌는지, 직접 서식과 섞일 때.
- `createTable`/`createTableEx` + 칸 글자 넣기: 표 너비(`colWidths`), 머리글 행 표현 방법(rhwp 에 머리글 행 속성이 있는지, 없으면 스타일·글자 모양으로), 칸 안 여러 문단.
- 양식 파일 본문 비우기: 구역 첫 문단 남기기, 본문 개체 지우기(SPEC-002 delete 규칙 재사용 가능 여부).
- 비교 기준: python-hwpx 로 만든 `~/Downloads/DocBridge_도입제안서_v0.1.hwpx` 가 한글에서 어떻게 보이는지(사용자 확인)와 rhwp 로 같은 내용을 만든 결과.

GO 기준: 빈 문서와 양식 문서 각각으로 제목·개요·본문·표가 든 문서를 만들어 한글에서 경고 없이 열리고 개요 번호·표가 맞다.

결과(#35, ADR 003): **rhwp 기준 GO, 한글 확인 대기.** 빈 문서 템플릿에 "제목" 스타일이 없어 docbridge 가 더한다. `applyStyle` 은 직접 문단 모양이 있으면 번호가 안 붙어 스타일 문단 모양으로 덮는다. `createTable` 은 넣는 문단의 개요 모양을 표·칸·표 아래 빈 문단에 물려줘 바탕글 문단에 넣고 빈 문단은 지운다. 머리글은 rhwp 속성(제목 셀·제목 줄 반복)이 있다. 양식 비우기는 실제 한컴 문서 8개를 포함한 12개 문서에서 저장 검증 통과(74쪽 60ms). 한글 확인 파일: `node scripts/make-create-check.ts` → `~/Downloads/docbridge-create-check/`.

## 범위 밖

- 글자 크기·굵기·색·정렬 같은 직접 서식, 표 테두리·칸 배경색 직접 지정
- 새 스타일 만들기
- 그림·도형·수식·차트 넣기
- 머리말·꼬리말·쪽 번호 만들기·고치기(양식에 있는 것은 그대로 씀)
- 표 행·열 추가·삭제, 칸 병합 (다음 스펙 후보)
- 여러 문서 동시 열기(새 문서를 만들면 열린 문서를 대신한다)
- `.hwp` 로 저장

## 기술 메모

- rhwp 0.8.7 API: `createBlankDocument()`(번들 `blank2010.hwp`, 한글 호환), `HwpDocument.createEmpty()`(구역·단 정의 없음 — 한글 호환이 필요하면 쓰지 않는다고 rhwp 주석이 밝힘), `getStyleList`, `applyStyle(sec, para, styleId)`, `createTable`/`createTableEx({sectionIdx, paraIdx, charOffset, rowCount, colCount, treatAsChar?, colWidths?})`, `insertTableRow`/`insertTableColumn`(범위 밖이지만 있음).
- 새 도구는 SPEC-002 편집 공용 경로(스냅샷·depth 대조·바뀐 블록 표시·`ParagraphChanges`)에 편집 종류로 더한다. `insert_table` 은 "문단 넣기 + 표 넣기" 한 편집.
- 새 문서의 "원본"은 없다. 세션의 `sourcePath` 가 비어 있을 때 저장 규칙(원본 덮어쓰기 판정)을 건너뛰고 `path` 를 기본 경로로 쓴다.
- 기술 검증 프로토타입: `src/core/create-document.ts` — `paragraphStyles`·`styleIdByName`(한글·영문 이름)·`applyParagraphStyle`(applyStyle + 스타일 문단 모양)·`ensureTitleStyle`·`insertTableParagraph`(새 문단 → 바탕글 → createTable → 표 아래 빈 문단 지우기 → 칸 채우기 → 머리글)·`clearTemplateBody`(남길 문단 사이 deleteRange, 남긴 문단의 다른 컨트롤 deleteControlAt). 근거와 측정은 ADR 003.
- 스타일 종류는 가장 낮은 비트만 본다(1 = 글자 스타일). 한컴 HWP 5 바이너리 일부는 문단 스타일 종류 값이 4·108 로 온다.
- `getControls` 는 본문을 목록 0 하나로 보고 문단 번호를 구역을 이어 센다(여러 구역 문서).
- `createTableEx` 의 `colWidths` 는 `treatAsChar: true` 에서만 쓰인다. 열 너비를 정하는 입력은 두지 않는다.
- 스타일을 주지 않은 `insert_paragraph` 는 SPEC-002 대로 기준 문단 모양을 따른다. "제목" 문단 뒤에 스타일 없이 넣으면 새 문단도 제목 모양이다(rhwp `insertParagraph` 는 다음 스타일을 쓰지 않는다).

## 열린 질문

- ~~`path` 를 필수로 할지~~ → **필수, 절대 경로 또는 `~` 만**(상대 경로 거부). 새 문서에는 상대 경로 기준(원본 폴더)이 없다 (#35, ADR 003)
- ~~표 머리글 행을 어떻게 표현할지~~ → **rhwp 속성(제목 셀 + 제목 줄 반복) + 굵은 글자** (#35, ADR 003)
- ~~양식 본문을 비울 때 표·그림을 지울지 남길지~~ → **지운다.** 머리말·꼬리말·쪽 번호 위치는 남긴다 (#35, ADR 003)
- ~~스타일 이름이 한글 판·영문 판에서 다를 때 영문 이름도 받을지~~ → 받는다(rhwp 스타일에 영문 이름이 있다, #35 프로토타입). 영문 판 한글에서의 확인은 못 했다
