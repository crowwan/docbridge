# SPEC-001 연결과 묻기

## 배경과 목표

받은 한글 문서에 대해 Claude 채팅에서 바로 묻고, 답의 근거를 원래 모양 그대로 띄운 문서 위에서 확인하고 싶다. 범용 AI 는 HWP 를 읽기만 하거나 아예 못 올리고, 읽더라도 "어디에 그렇게 써 있는지"를 원문 화면에서 보여주지 못한다.

이 스펙이 끝나면:
- Claude Desktop(또는 Cowork·Code)에 docbridge 를 한 번 등록해 두고, 채팅에서 "이 파일 열어줘"라고 하면 브라우저에 문서가 원래 모양으로 뜬다.
- 문서 내용을 물으면 Claude 가 문서를 블록 단위로 읽고 답하며, **근거 부분이 뷰어에서 하이라이트**된다.

편집(바꾸기·이동·저장)은 SPEC-002 에서 다룬다. 이 스펙은 읽기 전용이다.

## 동작 정의

### 구성

```
Claude 채팅 ──stdio── docbridge MCP 서버 ──WebSocket── 브라우저 뷰어
                       (Node, 내 PC)        127.0.0.1    (서버가 띄우는 로컬 페이지,
                                            + 세션 토큰    @rhwp/core 로 렌더링)
```

- MCP 서버가 뷰어 페이지도 직접 제공한다: `http://127.0.0.1:<포트>/?token=<세션 토큰>`. 포트 기본값은 7790(`DOCBRIDGE_PORT` 로 변경), 사용 중이면 다음 포트로 넘어가 **10개(7790~7799)까지** 시도한다. 모두 사용 중이면 "포트 7790~7799 이 모두 사용 중입니다. DOCBRIDGE_PORT 로 다른 포트를 정하세요." 를 남기고 시작하지 않는다. `DOCBRIDGE_PORT` 가 숫자가 아니거나 범위(1~65535, 0 은 빈 포트 아무거나 — 테스트용) 밖이면 "DOCBRIDGE_PORT 가 올바른 포트 번호가 아닙니다: <값>" 을 남기고 시작하지 않는다. 비어 있으면 기본값. 3000 은 쓰지 않는다.
- 서버와 뷰어는 WebSocket 으로 요청/응답한다(서버가 요청 id 를 붙여 보내고 뷰어가 같은 id 로 응답, `src/shared/protocol.ts`). 뷰어가 **30초** 안에 응답하지 않으면 그 요청은 "뷰어가 30초 안에 응답하지 않았습니다(<요청>). 뷰어 탭을 확인하고 다시 시도하세요." 오류로 끝난다. 요청은 마지막에 붙은 뷰어 탭이 받는다.
- 문서 상태의 기준은 브라우저 뷰어다. 서버는 파일을 읽어 뷰어에 넘기고, Claude 의 도구 호출을 뷰어에 전달할 뿐 문서를 따로 들고 있지 않는다. 블록 추출·찾기·하이라이트 좌표 계산은 뷰어(`@rhwp/core`)가 하고, 서버는 마지막 파일 경로와 블록 id 표만 기억한다.
- v0.1 에서는 **한 번에 문서 하나**만 연다. 다른 파일을 열면 이전 문서를 닫고 바꾼다.

### MCP 도구

도구 이름은 한글 포맷에 묶이지 않게 짓는다.

| 도구 | 입력 | 결과 |
|---|---|---|
| `open_document` | `path` (로컬 파일 경로, `~/` 가능) | 연결된 뷰어가 없으면 기본 브라우저로 뷰어 주소를 연다(30초 안에 뷰어가 붙지 않으면 뷰어 주소와 함께 오류). 이미 연결된 뷰어가 있으면 새 탭을 열지 않고 그 탭의 문서를 바꾼다. 문서를 띄우고 문서 요약(파일 이름, 쪽 수, 블록 수)과 뷰어 주소를 돌려준다 |
| `get_outline` | 선택 `from`(블록 id, 이어 받기) | `{ blockCount, blocks, more? }`. `blocks` 는 문서 순서대로 `{ id, kind, page, text, number?, outlineLevel?, name? }` — `kind` 는 `paragraph`(문단)·`table`(표)·`field`(누름틀), `page` 는 1부터인 쪽, `text` 는 앞 40자(넘으면 끝에 `…`, 표는 칸 텍스트를 ` \| ` 로 이은 것, 누름틀은 값), 자동 번호면 `number`(번호 문자열), 개요 문단이면 `outlineLevel`(1부터), 누름틀이면 `name`. 한 번에 500블록 |
| `read_blocks` | `ids`(블록 id 목록) 또는 `fromPage`·`toPage`(1부터, `toPage` 없으면 한 쪽) + 선택 `from`(쪽 범위 안에서 이 id 부터). 잘못된 조합·범위는 오류(예외 절) | `{ blocks, more? }`. `ids` 면 준 순서(중복 제거), 쪽 범위면 문서 순서. 문단 `{ id, kind, page, text, number?, outlineLevel? }`, 표 `{ id, kind, page, rowCount, colCount, cells }` — `cells` 는 칸마다 `{ row, col, text, rowLabel }`(`행,열` 은 0부터, `text` 는 칸 안 문단을 `\n` 으로 이은 것, `rowLabel` 은 같은 행 첫 칸 텍스트), 누름틀 `{ id, kind, page, name, guide, value, inTable }`. 잘린 블록은 `truncated: true` |
| `find_text` | `query`(1자 이상, 글자 그대로 비교) | `{ query, matchCount, matches }`. 일치마다 하이라이트 대상 `TextTarget`(아래 블록 절, `start`·`end` 채움) + `before`·`after`(앞뒤 20자) — `{ id, cell?: { row, col }, start, end, before, after }`, 표 칸 안이면 `cell`. 앞에서부터 겹치지 않게 모두 찾는다. 문단·표 칸에서 찾고 누름틀 블록은 따로 찾지 않는다(누름틀 값은 그 누름틀이 든 문단·칸 텍스트에 들어 있다) |
| `highlight` | 대상(`TextTarget`) 목록, 선택 `note` | 뷰어에 하이라이트를 그리고 첫 대상으로 스크롤한다. 이전 하이라이트는 지운다 |
| `clear_highlight` | 없음 | 하이라이트를 모두 지운다 |

### 블록

- 블록 = Claude 에게 보여주는 단위. 본문 문단 하나, 표 하나(칸은 표 안의 `행,열`), 누름틀 하나. 문서 순서는 문단 → 그 문단에 놓인 표 → 그 문단(또는 그 문단의 표 칸)에 든 누름틀.
- 글자가 없는 빈 문단(줄 띄우기용)은 블록으로 내보내지 않는다.
- 하이라이트·찾기 공용 대상 `TextTarget` = `{ id, cell?: { row, col }, start?, end? }` (`src/shared/protocol.ts` `textTargetSchema`).
  - `id`: 블록 id. `cell`: 표 블록일 때 칸(0부터), 표 블록인데 없으면 표 전체.
  - `start`·`end`: 블록 텍스트 안 글자 위치, 0부터, `start` 포함·`end` 미포함. 둘 다 없으면 블록(칸) 전체.
  - 블록 텍스트 = `read_blocks` 가 돌려주는 그 블록의 `text` 와 같은 문자열. 칸은 칸 안 문단을 `\n` 으로 이은 문자열(칸의 `text`, `\n` 도 한 글자).
  - `find_text` 결과에서 `before`·`after` 를 뺀 것을 `highlight` 에 그대로 넘긴다.
- 자동 번호 문자열은 뷰어가 그린 번호를 그대로 준다(개요 번호·문단 번호 모두). 번호를 직접 타이핑한 문단은 번호가 본문 텍스트에 들어 있고 번호 문자열은 비어 있다.
- `id` 는 docbridge 가 문서를 열 때 블록마다 문서 순서대로 부여하는 짧은 문자열이다(`b12` 처럼). 서버가 id → 문서 위치(구역·문단·문단 안 표/누름틀 순서) 대응표를 기억하고, docbridge 명령으로 문단을 넣거나 지우면 대응표의 위치를 같이 옮긴다. 그래서 SPEC-002 에서 문단을 넣고 지워도 id 가 바뀌지 않는다. 문서 파일 안에는 id 를 심지 않는다. 같은 파일을 다시 열면 새로 부여한다.
- 머리말·꼬리말·각주는 v0.1 에서 블록으로 내보내지 않는다.

### 기본 흐름

1. 사용자가 채팅에서 "~/Downloads/공문.hwpx 열어줘"라고 한다.
2. Claude 가 `open_document` 를 부른다. 브라우저에 뷰어 탭이 열리고(이미 열려 있으면 그 탭에서) 문서가 렌더링된다. 서버는 쪽 수·블록 수·뷰어 주소를 돌려준다.
3. 사용자가 "회신 기한이 언제야?"라고 묻는다.
4. Claude 가 `get_outline`·`find_text`·`read_blocks` 로 필요한 부분을 읽고 답한다.
5. Claude 가 근거 블록·범위로 `highlight` 를 부른다. 뷰어가 그 위치로 스크롤하고 노란 하이라이트를 그린다. `note` 가 있으면 하이라이트 옆에 짧게 보인다.
6. 다음 질문에서 새 하이라이트를 그리면 이전 것은 사라진다.

### 예외와 경계 상황

- **뷰어가 닫혀 있을 때**: 문서가 필요한 도구는 오류 "뷰어가 연결되어 있지 않습니다. open_document 로 다시 여세요."를 돌려준다. 이미 열었던 파일 경로를 " 마지막 파일: <절대 경로>" 로 덧붙인다(열린 문서가 없으면 붙이지 않는다). 요청 도중에 뷰어 연결이 끊겨도 같다.
- **열 수 없는 파일**: 아래는 파일을 읽지 않고(뷰어에 보내지 않고) 오류를 돌려준다.
  - 확장자가 `.hwp`/`.hwpx` 가 아니면(대소문자는 가리지 않는다): "열 수 없는 파일 형식입니다(.docx). .hwp, .hwpx 만 열 수 있습니다."
  - 없는 파일: "파일을 찾을 수 없습니다: <경로>"
  - **50MB** 를 넘는 파일: "파일이 너무 큽니다(<크기>MB). 50MB 까지 열 수 있습니다."
  - rhwp 가 읽지 못하면(손상, 암호, 배포용 문서) "문서를 열 수 없습니다: <rhwp 가 준 이유>" 를 돌려주고, 뷰어에는 "문서를 열 수 없습니다" 오류 화면(파일 이름과 이유)을 보여준다. 이전 문서는 닫힌다(서버도 열린 문서를 비운다). 그 뒤 문서가 필요한 도구는 "열린 문서가 없습니다. open_document 로 문서를 여세요." 를 돌려주고, 탭을 새로고침해도 이전 문서를 다시 띄우지 않는다.
- **없는 블록 id**: "없는 블록 id 입니다: b77, b88. get_outline 을 다시 불러 지금 블록 id 를 확인하세요." (`read_blocks` 의 `ids`·`from`, `get_outline` 의 `from`)
- **`read_blocks` 인자 오류**: 빈 결과로 돌려주지 않고 오류로 거부한다(빈 결과면 "그 쪽은 비었다"로 읽힌다).
  - 고를 방법이 없음(`toPage` 만 준 경우 포함): "읽을 블록을 ids 나 fromPage(·toPage) 로 정하세요."
  - `ids` 와 쪽 범위를 같이: "ids 와 쪽 범위(fromPage·toPage) 중 하나만 주세요."
  - `ids` 와 `from` 을 같이: "from 은 쪽 범위(fromPage·toPage)와 함께만 씁니다. ids 로 이어 읽을 때는 more.next 의 ids 를 그대로 주세요."
  - 0 이하 쪽: "쪽 번호는 1부터입니다(fromPage: 0)." (`toPage` 도 같다)
  - `fromPage` > `toPage`: "fromPage(5)가 toPage(2)보다 뒤입니다. fromPage 는 toPage 보다 작거나 같아야 합니다."
  - 문서 쪽 수 밖: "이 문서는 3쪽까지입니다(toPage: 9)." (쪽 수는 뷰어 조판 기준, `open_document` 결과의 쪽 수)
- **큰 문서**: `get_outline` 은 블록 500개, `read_blocks` 는 한 번에 글자 20,000자까지(내보내는 글자 필드를 모두 센다: 문단 텍스트·번호, 칸 텍스트와 칸마다 붙는 `rowLabel`, 누름틀 이름·안내문·값. `id`·`kind` 같은 구조 값은 세지 않는다). 넘으면 결과에 `more: { message, next }` 를 붙인다. `next` 는 다음에 같은 도구를 부를 인자 그대로다 — `get_outline` 은 `{ from: "b501" }`, `read_blocks` 는 남은 `{ ids }` 또는 `{ fromPage, toPage, from }`. 예: "블록이 620개라 1~500번째만 보냈습니다. 나머지는 get_outline 을 from: "b501" 로 다시 부르세요." / "글자가 20,000자를 넘어 블록 50개 중 20개만 보냈습니다. 나머지는 read_blocks 를 more.next 의 인자로 다시 부르세요."
  - `read_blocks` 는 넘기 전 블록까지 보낸다. 첫 블록이 혼자 20,000자를 넘으면 그 블록을 잘라(문단은 한도에 맞게 앞부분, 표는 들어가는 칸까지) `truncated: true` 로 보내고 "b7: 25,000자 중 앞 20,000자만 보냈습니다." 를 붙인다. 잘린 블록의 나머지는 v0.1 에서 이어 받지 못한다(`find_text` 로 위치를 찾아 문맥을 본다).
- **토큰 없는 연결**: 뷰어 주소에 세션 토큰이 없거나 틀리면 WebSocket 연결을 거부(HTTP 401)하고 "docbridge 가 연 탭이 아닙니다" 화면을 보여준다. 서버를 다시 띄우면 토큰이 바뀌므로 이전 탭도 이 화면이 된다.
- **뷰어 탭을 새로고침**: 같은 문서를 다시 띄우고 블록 id 는 유지한다(서버가 마지막 파일 경로와 id 표를 기억하고, 뷰어가 다시 붙으면 그 파일을 다시 읽어 보낸다). 다시 띄우는 동안 들어온 도구 요청은 끝날 때까지 기다린다. 그사이 파일이 바뀌어 블록 위치가 달라졌으면 블록 id 를 새로 붙이고(서버 로그에 남김), 파일이 사라졌으면 열린 문서를 비운다.

## 기술 검증 (첫 이슈)

기능 이슈 전에 다음을 확인하고 결과로 이 스펙과 ADR 을 고친다. **결과: GO** — 측정값·근거는 `docs/decisions/001-stack-and-rhwp.md`.

- `@rhwp/core`(0.8.7 고정)를 Vite 페이지에서 불러와 실제 공문·보고서 5개를 렌더링한다. 한 쪽 렌더링 시간, WASM 로딩 시간을 잰다.
- 블록 추출: 문단·표·누름틀 목록과 자동 번호 문자열을 뽑을 수 있는지 (`getStructure`, `getOutlineNavigation` 등).
- 하이라이트: `getSelectionRects` 좌표로 렌더링 결과 위에 오버레이를 정확히 겹칠 수 있는지.
- 블록 id 를 문단 객체에 붙일 방법(위치 인덱스 대응표로 충분한지).
- MCP SDK stdio 서버 + 같은 프로세스의 HTTP·WebSocket 서버가 Claude Desktop 에서 문제없이 같이 도는지.

GO 기준: 5개 문서 모두 렌더링되고, 하이라이트가 글자 위에 정확히 겹친다. 하나라도 안 되면 이유와 대안을 정리해 스펙을 고친다.

## 기술 메모

- 근거: `docs/research/rhwp-code-analysis.md` (구조 추출 API, `getSelectionRects`, 위치 인덱스의 불안정성), `docs/research/rhwp-issues-analysis.md` (버전 퇴행 — 0.8.2→0.8.7 텍스트 추출 누락 사례 → 버전 고정·회귀 세트 필요).
- rhwp 기존 MCP(`rhwp mcp-serve`)는 파일 기반이라 쓰지 않는다. 비교용으로만 같이 등록해 볼 수 있다.
- 테스트용 문서는 개인정보 없는 공개 양식으로 `fixtures/` 에 둔다(중첩 표·표 안 그림·직인·각주·수식이 없는 것부터).
- 하이라이트 자동 테스트는 Playwright 로 뷰어를 띄우고 오버레이 요소의 위치를 `getSelectionRects` 결과와 비교하고, 캔버스의 글자 잉크가 사각형 안에 있는지 본다.
- rhwp 0.8.7 `getSelectionRects` 는 범위가 줄 첫 글자에서 시작하면 사각형 왼쪽을 단 왼쪽 끝으로 준다(가운데 정렬·번호·내어쓰기 줄에서 글자 밖까지 칠해짐). 줄마다 `getCursorRectOnLine` 으로 왼쪽을 바로잡는다(`src/core/highlight-rects.ts`, ADR 001).
- 문단 번호(Number) 문자열은 API 가 따로 없어 쪽 글자 배치(`getPageTextLayout`)에서 문단 첫 글자 앞에 그려진 번호를 읽는다. 개요 번호는 `getOutlineNavigation` 과 같은 값이다(`src/core/blocks.ts`). 글자 배치는 번호·개요 문단이 시작하는 쪽만 읽고, 거기서 못 찾으면 다음 쪽도 본다(쪽 나눔으로 시작하는 문단).
- 표 위치(`getControls` 의 `para`)는 구역을 이어 붙인 문단 번호라 구역 첫 문단 번호를 `getParagraphCount` 합으로 구한다. `getSectionStarts` 는 구역 정의 표식이 든 문단까지 구역 시작으로 세서(구역 하나에 `[0,1]`) 쓰지 않는다(#6).
- 블록은 뷰어가 문서를 열 때 한 번 뽑아 들고 있고(읽기 전용), `get_outline`·`read_blocks` 는 뷰어에서 블록 전문을 받아 서버가 id 를 붙이고 고르고 자른다. `find_text` 는 뷰어가 찾아 블록 위치를 주고 서버가 id 로 바꾼다.
- rhwp 버전을 올릴 때 fixture 별 `get_outline` 결과를 `tests/outline/*.json` 과 비교한다(쪽 번호는 Node 근사 기준).
- 쪽 번호는 브라우저 조판 기준이다. Node 에서 같은 WASM 을 돌리면 글자 폭을 근사해서 쪽 나눔이 다르다.
- 실제 기안문 서식은 기관명·수신·제목·결재란이 표 안 누름틀이고, 결재란은 표 안 표다. 표 안 표의 칸 텍스트는 바깥 표 블록에 나오지 않는다(누름틀 블록으로는 나온다).
