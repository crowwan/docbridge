# SPEC-001 연결과 묻기

## 배경과 목표

받은 한글 문서에 대해 Claude 채팅에서 바로 묻고, 답의 근거를 원래 모양 그대로 띄운 문서 위에서 확인하고 싶다. 범용 AI 는 HWP 를 읽기만 하거나 아예 못 올리고, 읽더라도 "어디에 그렇게 써 있는지"를 원문 화면에서 보여주지 못한다.

이 스펙이 끝나면:
- Claude Desktop(또는 Cowork·Code)에 docbridge 를 한 번 등록해 두고, 채팅에서 "이 파일 열어줘"라고 하면 브라우저에 문서가 원래 모양으로 뜬다.
- 문서 내용을 물으면 Claude 가 문서를 블록 단위로 읽고 답하며, **근거 부분이 뷰어에서 하이라이트**된다.

편집(바꾸기·이동·저장)은 SPEC-002 에서 다룬다. 이 스펙은 읽기 전용이다.

## 동작 정의

### 구성

```
Claude 채팅 ──stdio── docbridge MCP 서버 ──WebSocket── 브라우저 뷰어
                       (Node, 내 PC)        127.0.0.1    (서버가 띄우는 로컬 페이지,
                                            + 세션 토큰    @rhwp/core 로 렌더링)
```

- MCP 서버가 뷰어 페이지도 직접 제공한다: `http://127.0.0.1:<포트>/?token=<세션 토큰>`. 포트 기본값은 7790, 사용 중이면 다음 빈 포트. 3000 은 쓰지 않는다.
- 문서 상태의 기준은 브라우저 뷰어다. 서버는 파일을 읽어 뷰어에 넘기고, Claude 의 도구 호출을 뷰어에 전달할 뿐 문서를 따로 들고 있지 않는다.
- v0.1 에서는 **한 번에 문서 하나**만 연다. 다른 파일을 열면 이전 문서를 닫고 바꾼다.

### MCP 도구

도구 이름은 한글 포맷에 묶이지 않게 짓는다.

| 도구 | 입력 | 결과 |
|---|---|---|
| `open_document` | `path` (로컬 파일 경로) | 뷰어가 없으면 기본 브라우저로 연다. 문서를 띄우고 문서 요약(파일 이름, 쪽 수, 블록 수)을 돌려준다 |
| `get_outline` | 없음 | 블록 목록: `id`, `kind`(문단·표·누름틀), 위치(쪽), 앞 40자, 자동 번호면 번호 문자열, 개요 수준 |
| `read_blocks` | `ids` 또는 쪽 범위 | 블록 전문. 표는 칸마다 `행,열`, 텍스트, 같은 행 첫 칸(라벨)을 함께 준다 |
| `find_text` | `query` | 일치하는 블록 `id` 와 블록 안 범위(시작·끝 글자 위치), 앞뒤 20자 |
| `highlight` | 블록 `id` 목록 또는 `id`+범위 목록, 선택 `note` | 뷰어에 하이라이트를 그리고 첫 대상으로 스크롤한다. 이전 하이라이트는 지운다 |
| `clear_highlight` | 없음 | 하이라이트를 모두 지운다 |

### 블록

- 블록 = Claude 에게 보여주는 단위. 본문 문단 하나, 표 하나(칸은 표 안의 `행,열`), 누름틀 하나.
- `id` 는 docbridge 가 문서를 열 때 블록마다 부여하는 짧은 문자열이다(`b12` 처럼). 문서 위치가 아니라 블록 자체를 가리켜서, SPEC-002 에서 문단을 넣고 지워도 바뀌지 않는다. 같은 파일을 다시 열면 새로 부여한다.
- 머리말·꼬리말·각주는 v0.1 에서 블록으로 내보내지 않는다.

### 기본 흐름

1. 사용자가 채팅에서 "~/Downloads/공문.hwpx 열어줘"라고 한다.
2. Claude 가 `open_document` 를 부른다. 브라우저에 뷰어 탭이 열리고 문서가 렌더링된다. 서버는 쪽 수·블록 수를 돌려준다.
3. 사용자가 "회신 기한이 언제야?"라고 묻는다.
4. Claude 가 `get_outline`·`find_text`·`read_blocks` 로 필요한 부분을 읽고 답한다.
5. Claude 가 근거 블록·범위로 `highlight` 를 부른다. 뷰어가 그 위치로 스크롤하고 노란 하이라이트를 그린다. `note` 가 있으면 하이라이트 옆에 짧게 보인다.
6. 다음 질문에서 새 하이라이트를 그리면 이전 것은 사라진다.

### 예외와 경계 상황

- **뷰어가 닫혀 있을 때**: 문서가 필요한 도구는 오류 "뷰어가 연결되어 있지 않습니다. open_document 로 다시 여세요."를 돌려준다. 이미 열었던 파일 경로를 함께 알려준다.
- **열 수 없는 파일**: 확장자가 `.hwp`/`.hwpx` 가 아니면 열지 않는다. rhwp 가 읽지 못하면(손상, 암호, 배포용 문서) 이유를 돌려주고 뷰어에는 오류 화면을 보여준다.
- **없는 블록 id**: 해당 id 를 알려주고 `get_outline` 을 다시 부르라고 안내한다.
- **큰 문서**: `get_outline` 은 블록 500개, `read_blocks` 는 한 번에 글자 20,000자까지. 넘으면 잘린 지점과 다음 요청 방법을 함께 돌려준다.
- **토큰 없는 연결**: 뷰어 주소에 세션 토큰이 없거나 틀리면 WebSocket 연결을 거부하고 "docbridge 가 연 탭이 아닙니다" 화면을 보여준다.
- **뷰어 탭을 새로고침**: 같은 문서를 다시 띄우고 블록 id 는 유지한다(서버가 마지막 파일 경로와 id 표를 기억).

## 수용 기준

- [ ] AC-1 `open_document` 에 `.hwpx`·`.hwp` 경로를 주면 뷰어가 문서를 렌더링하고 쪽 수·블록 수를 돌려준다 (자동)
- [ ] AC-2 확장자가 `.hwp`/`.hwpx` 가 아니면 파일을 읽지 않고 오류를 돌려준다 (자동)
- [ ] AC-3 서버는 127.0.0.1 에서만 열리고, 세션 토큰이 없거나 틀린 WebSocket 연결을 거부한다 (자동)
- [ ] AC-4 `get_outline` 은 본문 문단·표·누름틀을 문서 순서대로 `id`·`kind`·쪽·앞 40자와 함께 돌려주고, 자동 번호 문단은 번호 문자열을 포함한다 (자동)
- [ ] AC-5 `read_blocks` 는 표 블록에 대해 칸마다 `행,열`·텍스트·같은 행 첫 칸 텍스트를 돌려준다 (자동)
- [ ] AC-6 `find_text` 는 일치하는 모든 위치의 블록 `id`·범위·앞뒤 20자를 돌려준다 (자동)
- [ ] AC-7 `highlight` 를 부르면 뷰어에 대상 범위의 하이라이트가 그려지고 첫 대상이 화면에 보이도록 스크롤되며, 이전 하이라이트는 지워진다 (자동)
- [ ] AC-8 뷰어가 연결되어 있지 않을 때 문서가 필요한 도구는 정해진 오류 문구와 마지막 파일 경로를 돌려준다 (자동)
- [ ] AC-9 `get_outline` 결과가 500블록, `read_blocks` 결과가 20,000자를 넘으면 잘라서 돌려주고 이어 받는 방법을 알려준다 (자동)
- [ ] AC-10 뷰어 탭을 새로고침해도 같은 문서가 다시 뜨고 블록 id 가 그대로다 (자동)
- [ ] AC-11 Claude Desktop 에 등록한 뒤 실제 공문으로 "열기 → 질문 → 답과 근거 하이라이트"가 끝까지 된다 (수동 QA)

## 기술 검증 (첫 이슈)

기능 이슈 전에 다음을 확인하고 결과로 이 스펙과 ADR 을 고친다.

- `@rhwp/core`(0.8.x 고정)를 Vite 페이지에서 불러와 실제 공문·보고서 5개를 렌더링한다. 한 쪽 렌더링 시간, WASM 로딩 시간을 잰다.
- 블록 추출: 문단·표·누름틀 목록과 자동 번호 문자열을 뽑을 수 있는지 (`getStructure`, `getOutlineNavigation` 등).
- 하이라이트: `getSelectionRects` 좌표로 렌더링 결과 위에 오버레이를 정확히 겹칠 수 있는지.
- 블록 id 를 문단 객체에 붙일 방법(위치 인덱스 대응표로 충분한지).
- MCP SDK stdio 서버 + 같은 프로세스의 HTTP·WebSocket 서버가 Claude Desktop 에서 문제없이 같이 도는지.

GO 기준: 5개 문서 모두 렌더링되고, 하이라이트가 글자 위에 정확히 겹친다. 하나라도 안 되면 이유와 대안을 정리해 스펙을 고친다.

## 기술 메모

- 근거: `docs/research/rhwp-code-analysis.md` (구조 추출 API, `getSelectionRects`, 위치 인덱스의 불안정성), `docs/research/rhwp-issues-analysis.md` (버전 퇴행 — 0.8.2→0.8.7 텍스트 추출 누락 사례 → 버전 고정·회귀 세트 필요).
- rhwp 기존 MCP(`rhwp mcp-serve`)는 파일 기반이라 쓰지 않는다. 비교용으로만 같이 등록해 볼 수 있다.
- 테스트용 문서는 개인정보 없는 공개 양식으로 `fixtures/` 에 둔다(중첩 표·표 안 그림·직인·각주·수식이 없는 것부터).
- 하이라이트 자동 테스트는 Playwright 로 뷰어를 띄우고 오버레이 요소의 위치를 `getSelectionRects` 결과와 비교한다.
