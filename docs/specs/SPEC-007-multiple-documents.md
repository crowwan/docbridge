# SPEC-007 여러 문서 동시에 열기와 문서 사이 복사

## 배경과 목표

지금 docbridge 는 문서를 하나만 연다. 새 문서를 열면 앞 문서를 대신한다(SPEC-002 "새 문서를 열면"). 그런데 받은 한글로 하는 일의 상당수는 **두 문서 사이**에서 일어난다:

- "공고문의 신청 자격을 신청서 표에 채워줘"
- "작년 보고서 3장을 올해 보고서에 가져와"
- "두 공문의 회신 기한이 다른지 봐줘"

이 스펙이 끝나면 여러 문서를 브라우저 탭마다 하나씩 띄워 두고, Claude 가 문서를 골라 읽고 고치며, 문단·표를 한 문서에서 다른 문서로 서식째 복사할 수 있다.

## 동작 정의

### 문서 이름(doc)

- `open_document`·`create_document` 는 앞 문서를 대신하지 않고 **새 탭**에 문서를 연다. 결과에 문서 이름 `doc`(`d1`, `d2` … — 서버가 매기고 닫아도 다시 쓰지 않는다)을 더한다.
- 같은 파일을 다시 열면 새 탭을 만들지 않고 그 문서 탭에 파일을 다시 읽어 띄우고 같은 `doc` 을 돌려준다(SPEC-002 "같은 파일을 다시 열면" 규칙은 그 문서 안에서 그대로 — 저장하지 않은 편집은 버리고 `warnings` 로 알리며 블록 id 를 새로 매긴다). 같은 파일은 그 문서의 마지막 파일(저장했으면 저장한 경로)과 실제 경로(링크를 따라간 경로 — macOS `/tmp` ↔ `/private/tmp` 등)가 같은 것이고, `open_document` 를 부른 순간에 가린다. 탭을 앞으로 보내지는 않는다(아래 "뷰어 탭").
- 두 문서가 같은 파일을 가리키지 않는다: `save_document` 의 저장 경로가 열린 다른 문서의 마지막 파일(실제 경로)이면 쓰지 않고 "d1 이 이 파일을 열고 있습니다: <경로>. 다른 경로에 저장하거나 d1 을 close_document 로 닫은 뒤 저장하세요." 오류.
- 저장 중(거부 확인 ~ 파일 쓰기를 마칠 때까지, 내보내기 포함)에는 그 파일을 막는다(#80 결정): 다른 문서가 그 경로를 `open_document` 하거나 `save_document` 하면 "d2 이 이 파일로 저장하는 중입니다: <경로>. 저장이 끝난 뒤 다시 하세요." 오류. 그대로 두면 저장을 마친 뒤 두 문서가 같은 파일을 가리켜(다시 열기·새로고침이 엉뚱한 문서로) 위 규칙이 깨진다. 저장이 끝나면(성공·실패 모두) 풀리고, 성공했으면 그 경로를 열면 저장한 문서가 된다. 자기 파일에 덮어 저장하는 중에 같은 파일을 다시 열면 막지 않고 그 문서의 줄에서 저장 뒤에 연다(같은 파일 다시 열기). 파일은 저장이 끝난 뒤에 읽는다 — 저장했으면 저장본, 저장이 실패했으면 디스크에 남은 옛 파일을 연다.
- 모든 문서 도구(읽기·하이라이트·편집·저장·스타일)에 `doc`(선택)을 더한다. 없으면 **마지막으로 쓴 문서**(마지막으로 열었거나 도구 대상이 된 문서). 문서가 하나면 지금과 똑같다.
- 블록 id 는 문서마다 따로다(`d1` 의 `b3` 과 `d2` 의 `b3` 은 다른 블록). 결과의 블록 id 는 지금처럼 `b3` 이고, 결과 맨 위에 `doc` 을 붙인다.
- 열 수 있는 문서는 8개까지(여는 중인 문서 포함, 같은 파일 다시 열기는 세지 않는다). 넘으면 "열린 문서가 8개입니다. close_document 로 닫아 주세요." 오류(`create_document` 도 같다).
- "마지막으로 쓴 문서" 가 닫히면(close_document·탭 닫기) 그 앞에 쓴 문서가 대상이 된다. 결과 맨 위 `doc` 으로 어느 문서였는지 보인다.
- 도구 결과에 붙는 알림(새로고침으로 사라진 편집, 사람이 화면에서 고친 것 등)은 다른 문서의 것이면 앞에 문서 이름을 붙인다("d1: 사용자가 화면에서 고침: b11 글자"). 열린 문서가 하나뿐이면 붙이지 않는다(지금 문구 그대로).

### 새 도구

| 도구 | 입력 | 결과 |
|---|---|---|
| `list_documents` | 없음 | `{ documents: [{ doc, fileName, path, newDocument?, pageCount, unsavedEdits, current }] }` (연 순서) — `path` 는 마지막 파일(저장 전 새 문서는 처음 저장할 자리이고 `newDocument: true`), `current` 는 `doc` 을 안 줬을 때 대상. 여는 중인 문서는 빠진다 |
| `close_document` | `doc`(선택), `discard`(선택) | 문서를 닫는다: 뷰어 탭은 "문서를 닫았습니다" 화면이 되고(스크립트가 열지 않은 탭은 브라우저가 닫게 두지 않는다) 빈 탭으로 남아 다음에 여는 문서가 그 탭을 쓴다. 저장하지 않은 편집이 있으면 닫지 않고 "저장하지 않은 편집 n개가 있습니다. 저장하거나 discard: true 로 닫아 주세요.", 한 번도 저장하지 않은 새 문서는 편집이 없어도 "저장하지 않은 새 문서 <이름> 입니다(편집 n개). 저장하거나 discard: true 로 닫아 주세요." (SPEC-003 — 되살릴 파일이 없다). `discard: true` 면 버리고 닫고 버린 것을 `warnings` 로 알린다(SPEC-002·003 의 버린 편집 문구). 결과 `{ doc, closed: true, warnings? }` |
| `copy_blocks` | `from`(원본 doc), `ids`(원본 블록, 이어진 범위), `to`(대상 doc), `before`·`after`(대상 블록) | 원본 문단·표를 서식째 대상 문서에 넣는다(원본은 그대로). 대상 문서의 편집 하나(undo 한 번, 되돌리기 이름 `copy_blocks d1 b11, b12 → before b7`). 결과 `{ doc(대상), inserted: [새 블록 id — 넣은 문단의 문단 글자·표·누름틀마다, 문서 순서], changed: [{ id, number?, text }], warnings? }` — changed 는 넣은 블록과 대상에서 번호가 다시 매겨진 문단, warnings 는 화면에 표시하지 못한 블록. 대상 문서가 마지막으로 쓴 문서가 된다(`from`·`to` 를 모두 확인한 뒤 고른다 — 없는 문서가 있으면 오류만 내고 마지막으로 쓴 문서는 그대로). 가져올 수 없는 개체가 든 문단이 있으면 아무것도 넣지 않고 거부("이 문단은 복사할 수 없습니다(각주): b3. 글자만 가져오려면 read_blocks 와 insert_paragraph 를 쓰세요." — 이유는 `move_blocks` 와 같은 목록, id 는 원본 블록). 원본 범위 오류는 앞에 "원본 d1: " |

### 복사 규칙(`copy_blocks`)

- 원본 범위 규칙은 `move_blocks` 와 같다(id 표로 이어진 블록, 같은 문단 블록은 문단째). 범위가 여러 구역에 걸치면 거부(구역마다 나눠 복사).
- 원본 탭이 원본을 HWPX 로 내보내 다시 열어 블록이 같은지 확인한 바이트(저장 전 검증과 같다)로 복사한다. 확인에 실패하면 복사하지 않는다.
- 글자 모양·문단 모양은 원본 것을 대상 문서로 가져온다. 대상에 같은 스타일 이름이 있으면 그 스타일(스타일 모양이던 글자·문단은 대상 스타일 모양, 굵게 등 직접 서식은 원본 그대로), 없으면 원본 스타일을 이름·모양 그대로 대상에 더한다(ADR 004). 같은 이름 스타일이 둘 남지 않는다. 더한 스타일의 다음 스타일이 대상에도 있는 이름이면 대상의 그 스타일을 가리킨다.
- 자동 번호 문단은 대상 위치의 번호를 따라 다시 매겨진다: 대상에 같은 모양의 번호 목록이 있으면 그 번호를 잇고(여럿이면 넣는 자리 바로 앞 문단의 목록), 없으면 새 번호 목록(1부터). 개요 문단은 대상 개요 번호를 따른다(ADR 004).
- 표·그림·누름틀이 든 문단은 그대로 복사한다. 옛 규칙의 도형·글상자도 거부 대상이 아니라 그대로 복사한다(한컴 문서의 사각형·그리기 개체 문단 — HWP 로 바꾼 핸들이 거부하면 HWPX 핸들로 가져온다, ADR 004). 각주·미주·머리말·꼬리말·감추기·책갈피·하이퍼링크 등 rhwp 가 가져오지 못하는 개체가 든 문단이 범위에 있으면 개체만 빼고 넣지 않고 블록째 거부한다(문단마다 이유, `move_blocks` 와 같은 목록 — ADR 004).
- 넣은 문단은 대상 문서 본문 폭으로 다시 배치된다(원본 폭 줄 배치를 가져오지 않는다 — 화면 표시·하이라이트·더블클릭 자리와 저장 파일 모두, #85, ADR 004).
- 저장한 파일에 줄 배치가 빠진 문단이 있으면(rhwp 가 다시 배치한 줄 배치를 빼고 저장하는 경우, 다른 도구가 저장한 파일) 문서를 열 때 다시 계산한다 — 다시 열어도 그 문단의 표시·하이라이트·더블클릭 자리가 줄마다 맞다. 줄 배치가 있는 문서는 블록·표시·저장 결과가 바뀌지 않는다(#89, ADR 004 결정 7).
- 대상 쪽 기준 규칙은 `insert_paragraph` 와 같다(구역 첫 문단 앞 거부).
- 표 칸 하나의 글자만 옮기는 일은 `read_blocks` + `replace_text` 로 한다(이 도구는 블록째).

### 뷰어 탭

- 문서마다 브라우저 탭 하나. 탭 제목은 파일 이름(새 문서는 `path` 의 이름, 저장하면 저장한 이름). 같은 서버·포트, 탭마다 WebSocket 연결 하나. 문서 탭 주소는 `?token=…&doc=d2` 이고, 연결할 때 이 이름을 서버에 알린다(새로고침해도 같은 문서로 다시 붙는다).
- 문서를 열 때 문서 이름 없이 붙은 빈 탭(뷰어 주소를 직접 연 탭, 문서를 닫았거나 열지 못한 탭)이 있으면 새 탭을 열지 않고 그 탭을 쓴다(서버가 문서와 함께 이름을 보내면 뷰어가 주소에 넣는다). 없으면 기본 브라우저로 그 문서 탭 주소를 연다.
- 뷰어 도구 막대에 `doc` 이름을 작게 보여 준다(Claude 가 "d2 에 넣었습니다" 할 때 어느 탭인지 알게).
- 도구가 대상으로 삼은 문서 탭을 앞으로 보내지는 않는다(브라우저가 막는 경우가 많다). 대신 하이라이트·편집이 생긴 탭은 탭 제목 앞에 `●` 를 붙이고, 그 탭을 보면 지운다.
- 사용자가 탭을 닫으면 그 문서는 열린 문서에서 빠진다(저장하지 않은 편집은 브라우저 확인 창 — SPEC-002 새로고침 규칙과 같음). 다음 도구 결과에 "d2 탭이 닫혀 문서를 닫았습니다" 를 알리고, 버려진 것이 있으면 괄호로 붙인다("d2 탭이 닫혀 문서를 닫았습니다(저장하지 않은 편집 1개를 버렸습니다)"). 브라우저는 탭 닫기와 새로고침을 가려 알려주지 않으므로, 문서 탭 연결이 끊긴 뒤 **5초** 안에 같은 문서 이름으로 다시 붙지 않으면 닫은 것으로 본다(그 사이 도구는 SPEC-001 미연결 오류).
- 사람 편집·⌘Z(SPEC-006)는 그 탭 문서의 직렬 큐·편집 기록으로 간다. 다른 문서를 열거나 만들거나 고쳐도 이 문서의 상태 번호는 그대로라 거부되지 않는다(다른 문서와 섞이지 않는다). 같은 파일 다시 열기·새로고침으로 그 문서가 바뀌면 SPEC-006 규칙대로 거부한다.

### 예외와 경계 상황

- `doc` 이 없는 이름이면 "열린 문서에 d5 가 없습니다. list_documents 로 확인해 주세요."
- `copy_blocks` 에서 `from` = `to` 면 같은 문서 안 복사로 된다(옮기기가 아니라 사본).
- 한 문서 탭을 새로고침하면 그 문서만 SPEC-002 새로고침 규칙대로 돌아간다.

## 수용 기준

- [x] AC-1 두 파일을 열면 탭 두 개, `doc` 이 `d1`·`d2` 로 나온다. 같은 파일을 다시 열면 같은 `doc` 이다 (자동)
- [x] AC-2 `doc` 없이 부른 도구는 마지막으로 쓴 문서를 대상으로 한다 (자동)
- [x] AC-3 문서마다 블록 id·되돌리기·저장하지 않은 편집 수가 따로다 (자동)
- [x] AC-4 `list_documents`·`close_document`(저장 안 한 편집 거부, `discard`) (자동)
- [x] AC-5 `copy_blocks` 가 문단·표를 서식째 다른 문서에 넣고, 대상 번호가 다시 매겨지며, `undo` 한 번에 돌아간다. 원본은 그대로다 (자동)
- [x] AC-6 대상에 같은 스타일이 없으면 원본 스타일 이름·모양 그대로 들어가고, 있으면 대상 스타일이 되며 같은 이름 스타일이 둘 남지 않는다 (자동)
- [x] AC-7 9번째 문서를 열면 거부한다 (자동)
- [x] AC-8 사용자가 탭을 닫으면 그 문서가 빠지고 다음 결과에 알린다 (자동 — E2E)
- [ ] AC-9 실제 공고문의 신청 자격을 실제 신청서에 복사해 저장한 파일이 한글에서 열리고 서식이 맞다 (수동 QA)

## 범위 밖

- 한 탭 안에서 문서를 나란히 보기(분할 화면)
- 문서 비교(diff) 화면 — 바뀐 내용 요약 기능과 함께 따로
- 문서 사이 끌어 놓기(SPEC-006 끌기는 한 문서 안)

## 기술 메모

- 서버(#63): `DocumentSession`(`src/server/session.ts`) 하나 = 문서 하나(id 표·편집 기록·state·직렬 큐·사람 편집 알림). 표 `DocumentSessions`(`src/server/documents.ts`)가 `doc → DocumentSession`, 이름 매기기, 같은 파일 찾기, 8개 상한, "마지막으로 쓴 문서"(쓴 순서), 탭 연결·끊김(새로고침·탭 닫기), 알림 모으기(다른 문서 알림 앞 이름)를 맡는다. 직렬 큐는 문서마다(다른 문서끼리 동시에 처리).
- 브리지(#63, `src/server/bridge.ts`): 연결마다 문서 이름(주소의 `&doc=`, 없으면 빈 탭)과 요청 추적을 따로 둔다. 요청은 그 문서의 마지막에 붙은 연결로, 응답은 같은 연결로. 빈 탭은 `claimViewer` 로 문서 탭이 되고, 닫은·열지 못한 문서 탭은 `releaseViewer` 로 빈 탭이 된다. 같은 문서의 이전 탭·빈 탭이 보낸 사람 편집은 거부.
- 프로토콜: `load_document`·`create_document` 에 `doc`(뷰어가 주소·도구 막대에 둔다), 새 메서드 `close_document`.
- 복사(ADR 004, #62 기술 검증): 원본 탭이 원본을 HWPX 바이트로 내보내 → 서버 → 대상 탭이 그 바이트를 열어 **HWP 로 한 번 바꾼 핸들**(번호·누름틀 문단은 HWPX 그대로 연 핸들이 거부한다, 거부되면 HWPX 핸들로 한 번 더)에서 `importParagraphBlock`. rhwp 는 글자·문단 모양·스타일·번호 정의·그림을 대상 정의와 내용으로 맞춰 다시 매기고, 없으면 대상에 더한다. docbridge 는 번호 정의(대상의 같은 모양 번호 목록·구역 개요 번호로)와 스타일(대상의 같은 이름으로, 쓰이지 않게 된 복제는 지우거나 "이름 사본N")만 보정한다(`src/core/copy-paragraphs.ts`). `exportSelectionHtml` → `pasteHtml` 대안은 번호·표·그림·스타일을 잃어 쓰지 않는다. 큰 문서(383쪽)는 원본 핸들 만들기에 1초대가 든다. 대상 쪽 보정은 넣은 문단만 보므로 대상 크기와 거의 상관없다(383쪽 대상에 13문단 약 0.22초, 대부분 `applyStyle`·`applyCellStyle` 의 구역 다시 조판 — ADR 004, #64).
- 메모리: 문서마다 WASM 문서 핸들이 탭에 따로 있다. 8개 상한은 큰 문서(수백 쪽)에서 탭 메모리를 보고 다시 정한다.

## 열린 질문

- ~~문서 사이 복사가 rhwp 공개 API 로 서식째 되는지~~ — 결정: **된다**(ADR 004, #62). `importParagraphBlock` + 번호·스타일 보정. 대상에 없는 스타일은 바탕글 + 직접 서식 대신 원본 스타일을 더하고, `warnings` 대신 블록째 거부로 바꿨다
- 탭 대신 한 탭 안 문서 목록(사이드바)이 나은지 — 결정: 기술 검증 후 (탭이 많아지면 찾기 어렵다)
