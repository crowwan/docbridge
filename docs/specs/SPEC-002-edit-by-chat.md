# SPEC-002 말로 고치기와 저장

## 배경과 목표

SPEC-001 로 받은 한글 문서를 Claude 채팅에서 열고 묻고 근거를 볼 수 있게 됐다. 이제 "3번 항목을 1번 위로 올려줘", "회신 기한을 11월 7일로 바꿔줘", "신청인 칸에 홍길동 넣어줘" 처럼 **말로 고치고**, 한글에서 그대로 열리는 파일로 **저장**하고 싶다. 예전 COM 방식 MCP 는 커서를 옮기고 범위를 고르는 도구를 수십 번 이어 불러야 해서 실패했다. docbridge 는 블록 단위 도구 한 번으로 끝낸다.

이 스펙이 끝나면:
- 채팅 한 마디로 문단 이동·넣기·지우기, 글자 바꾸기, 표 칸·누름틀 채우기를 하고, 뷰어에서 바뀐 곳을 바로 본다.
- 잘못 고쳤으면 "되돌려줘"로 되돌린다.
- 결과를 HWPX 로 저장한다. 원본은 덮어쓰지 않는 것이 기본이다.

## 동작 정의

### 원칙

- **바로 적용, 언제든 되돌리기.** 고칠지 말지는 사용자와 Claude 가 채팅에서 정한다. 도구는 부르면 바로 적용하고, 뷰어에 바뀐 곳을 표시하며, 되돌리기를 제공한다. (앱 안 [적용/취소] 카드는 두지 않는다 — AI 패널을 앱에 두지 않는다는 PRD 결정과 같다.)
- **서식은 문서에 있는 것을 따른다.** 글자를 바꾸면 바뀌는 자리 첫 글자의 글자 모양을, 새 문단은 기준 문단의 문단 모양과 글자 모양(앞에 넣으면 기준 문단 첫 글자, 뒤에 넣으면 마지막 글자 — 한글에서 문단 처음·끝에서 Enter 를 친 것과 같다)을 따른다. 서식을 정하는 도구는 두지 않는다. rhwp 의 기본 동작이 이와 다른 곳(넣은 글자가 앞 글자 모양을 따름, 옮긴 번호 문단의 번호가 1부터 다시 시작 등)은 docbridge 가 바로잡는다(ADR 002).
- **블록 id 는 유지된다.** 넣은 블록은 새 id 를 받고, 지운 블록의 id 는 다시 쓰지 않으며, 옮긴 블록은 id 가 그대로다 (SPEC-001 블록 id 대응표).
- 대상 지정은 SPEC-001 의 `TextTarget`(블록 id, 표 칸, 코드포인트 범위)을 그대로 쓴다.

### MCP 도구

| 도구 | 입력 | 결과 |
|---|---|---|
| `replace_text` | `target`(TextTarget), `text` | 범위의 글자를 `text` 로 바꾼다. `start`/`end` 가 없으면 블록(칸) 글자 전체, 누름틀 블록이면 값 전체(`start`/`end` 는 값 안 위치). 문단·표 칸·누름틀 값 모두. `text` 가 비면 범위를 지우고, 범위가 비면(`start` = `end`) 그 자리에 넣는다(누름틀 값 맨 앞·맨 뒤에 붙이기도 값 안에 들어간다). `text` 에 줄바꿈이 있으면 거부한다(새 문단은 `insert_paragraph`). 칸 범위가 칸 안 여러 문단에 걸치면 그 문단들이 하나로 합쳐진다. 빈 범위에 빈 `text` 는 바꿀 것이 없어 거부한다. 결과: 바뀐 블록 id, 바뀐 뒤 블록 앞 40자(표 칸이면 `cell` 과 그 칸 앞 40자). 바뀐 블록은 대상 블록과 같은 문단에 걸린 블록 모두다(누름틀 값을 바꾸면 그 문단 글자도, 문단 글자를 바꾸면 그 안 누름틀도 바뀐다 — 다음 편집은 새 글자 위치로) |
| `insert_paragraph` | `before` 또는 `after`(블록 id), `text` | 기준 블록 앞/뒤에 새 문단을 넣는다. 문단 모양은 기준 문단, 글자 모양은 앞에 넣으면 기준 문단 첫 글자·뒤에 넣으면 마지막 글자를 따른다(기준이 표·누름틀이면 그것이 든 문단). 기준이 번호 문단이면 새 문단도 번호를 받고 번호가 다시 매겨진다. `before`·`after` 는 하나만 준다. `text` 에 줄바꿈이 있으면 거부한다(문단 여럿은 문단마다 부른다). `text` 가 비면 빈 문단을 넣는다(빈 문단 블록으로 남고, 화면에 자리가 없어 `warnings` 에 표시 못함 안내). 결과: 새 블록 id(`inserted`)와 바뀐 블록(`changed` — 새 문단과, 번호 문단이라 번호가 다시 매겨져 번호 문자열이 달라진 문단) |
| `delete_blocks` | `ids` | 블록(문단·표)을 지운다. 여러 id 도 편집 하나다(`undo` 한 번에 모두 돌아온다). 문단 블록을 지우면 그 문단이 통째로 지워져 같은 문단에 든 표·누름틀도 같이 지워진다. 표 블록을 지우면, 표가 든 문단에 다른 블록(문단 글자·다른 표·누름틀)이 없으면 문단째(빈 줄이 남지 않게), 있으면 표만 지운다(문단 글자는 남는다). 누름틀 블록은 지울 수 없다(값 비우기는 `replace_text`). 구역 첫 문단은 지울 수 없다(아래 예외). 뷰어는 다시 그리고(이전 표시는 지워진다), 지운 블록은 표시하지 않는다. 남은 번호 문단이 다시 매겨져 번호 문자열이 달라지면 그 문단에만 초록 테두리를 남긴다("가. 나. 다." 중 가·다를 지우면 "가." 가 된 문단). 결과: 지운 id(`deleted`, 같이 지워진 표·누름틀 id 포함, 문서 순서) |
| `move_blocks` | `ids`(문서에서 이어진 블록들), `before` 또는 `after`(블록 id, 둘 중 하나만) | 블록이 든 본문 문단을 서식째(표·누름틀 포함) 기준 블록이 든 문단 앞/뒤로 옮긴다. 옮기는 단위는 문단이라, 고른 블록과 같은 문단에 걸린 블록(문단 안 누름틀, 표 문단의 표)과 고른 블록 사이의 빈 문단도 같이 옮겨진다. 블록 id 는 그대로다. 자동 번호는 새 순서로 다시 매겨진다. 결과: `moved`(옮긴 블록 id, 문서 순서), `changed`(옮긴 블록과 번호가 바뀐 문단의 블록 — 블록마다 `id`, 자동 번호면 옮긴 뒤 `number`, 앞 40자 `text`), `warnings`(직접 입력한 번호, 표시 못 한 블록) |
| `undo` | `steps`(기본 1, 1~20) | 편집을 최근 것부터 되돌린다. 최대 20단계. 되돌릴 수 있는 것보다 많이 달라면 있는 만큼 되돌리고 경고를 담는다. 결과: 되돌린 수, 되돌린 편집 요약(`replace_text b11` 처럼, 최근 것부터) |
| `save_document` | `path`(선택), `overwrite`(기본 false) | 현재 문서를 HWPX 로 저장한다(아래 "저장"). 결과: `{ path, bytes, verified: { blockCount }, warnings? }` — 저장 경로(절대), 파일 크기(바이트), 검증한 블록 수, 내보내기 손실 경고 |

편집 도구는 모두 뷰어를 다시 그리고, **바뀐 블록에 초록 테두리 표시**를 남긴다(다음 편집이나 하이라이트 때 지워짐). 자동 번호가 다시 매겨져 번호 문자열이 달라진 문단도 바뀐 블록이다(옮기기·넣기·지우기). 근거 하이라이트(SPEC-001)와 구분되는 색이다. 테두리는 블록 전체(문단은 글자가 있는 줄들, 표는 표 전체, 누름틀은 값)를 쪽마다 하나로 감싸고, 보이지 않으면 그 자리로 스크롤한다. 다시 그리면 이전 근거 하이라이트도 지워진다. 문단 안 누름틀처럼 다른 테두리 안에 드는 테두리는 겹쳐 그리지 않는다. 글자를 모두 지운 빈 문단처럼 화면에 자리가 없는 블록은 표시하지 않고 결과 `warnings` 에 "<id>: 화면에 표시할 자리가 없어(빈 문단 등) 바뀐 블록 표시를 하지 못했습니다." 를 담는다. `undo` 뒤에는 표시를 남기지 않는다. 다시 그리기·표시가 실패하면 그 편집은 되돌리고(스냅샷) 오류를 돌려준다. 편집 뒤에는 보던 자리를 그대로 두고, 새 문서는 맨 위부터 보인다.

**빈 문단 블록.** 문서를 열 때 글자가 없는 문단은 블록으로 내보내지 않지만(SPEC-001), 편집으로 글자를 모두 지운 문단은 같은 id 의 빈 문단 블록으로 남아 다시 채울 수 있다.

### 저장

- 저장 형식은 항상 HWPX 다. 원본이 `.hwp` 여도 `.hwpx` 로 저장한다.
- "원본"은 `open_document` 로 연 파일이다(저장한 뒤에도 바뀌지 않는다).
- `path` 가 없으면 원본과 같은 폴더에 `<원본 이름>-수정.hwpx`. 이미 있으면 `-수정-2`, `-수정-3` … 중 처음 비어 있는 이름(두 번 저장하면 `-수정`, `-수정-2` 두 파일이 생긴다).
- `path` 는 절대 경로, `~/`(홈 폴더), 상대 경로(**원본 폴더 기준** — 서버 프로세스의 작업 폴더는 사용자가 모른다)를 받는다. 폴더(끝이 `/` 이거나 이미 있는 폴더)를 가리키면 확장자를 붙이지 않고 "폴더입니다: <경로>. 파일 경로를 주세요." 로 거부한다. 확장자가 없으면 `.hwpx` 를 붙이고(붙인 뒤의 경로로 원본·기존 파일을 판단한다), `.hwpx`(대소문자 무시)가 아닌 확장자는 거부한다: "HWPX 로만 저장합니다(<확장자>). 경로를 .hwpx 로 끝내거나 확장자를 빼세요."
- `overwrite` 는 `path` 를 줬을 때만 뜻이 있다. `path` 가 없으면 `overwrite: true` 여도 늘 기본 이름을 새로 만든다(겹치면 번호). **원본을 덮어쓰려면 `path` 에 원본 경로를 주고 `overwrite: true`.**
- `path` 가 원본 파일이면 `overwrite: true` 이고 원본이 `.hwpx` 일 때만 덮어쓴다. `overwrite` 가 없으면 "원본 파일입니다: <경로>. 덮어쓰려면 overwrite: true 를 주세요.", 원본이 `.hwp` 면 `overwrite: true` 여도 "원본(.hwp)은 덮어쓸 수 없습니다. 저장은 항상 HWPX 입니다. path 를 빼면 <원본 이름>-수정.hwpx 로 저장합니다." (같은 파일인지는 링크를 따라간 장치·inode 로 본다 — 대소문자만 다른 경로, 원본을 가리키는 `.hwpx` 이름의 심볼릭·하드 링크도 원본이다. 쓰기 직전에도 다시 본다)
- 이미 있는 다른 파일은 `overwrite: true` 일 때만 덮어쓴다: "이미 있는 파일입니다: <경로>. 덮어쓰려면 overwrite: true 를 주세요." 폴더가 없으면 "저장할 폴더가 없습니다: <폴더>", 경로가 폴더면 "폴더입니다: <경로>. 파일 경로를 주세요."
- 경로 검사는 내보내기 전에 한다(경로가 틀리면 내보내지 않는다).
- 저장은 열기·새로고침·편집·되돌리기와 같은 줄에 서서 하나씩 한다. 저장하는 사이 들어온 `open_document`·편집은 저장이 끝난 뒤에 하므로, 내보낸 문서와 저장 상태(마지막 파일·저장하지 않은 편집 수)가 같은 편집 시점이다.
- **저장 전 검증**: 내보낸 HWPX 를 rhwp 로 다시 열어 블록 수와 블록별 글자(위치·번호·칸·누름틀 값 포함)가 지금 문서와 같은지 비교한다. 다르면 파일을 쓰지 않고 "저장 전 검증에 실패해 파일을 쓰지 않았습니다. 다시 연 문서와 다른 블록: <id 목록>." (다시 연 문서에 블록이 더 있으면 " 다시 연 문서에 블록이 <n>개 더 있습니다." 를 붙인다), 다시 열지 못하면 "저장 전 검증에 실패해 파일을 쓰지 않았습니다. 내보낸 HWPX 를 다시 열지 못했습니다: <rhwp 가 준 이유>" 를 돌려준다. rhwp 의 내보내기 보고서(`exportHwpxWithReport`)에 손실 항목이 있으면 파일은 쓰고 결과 `warnings` 에 "HWPX 로 내보내며 빠지거나 줄어든 내용이 있습니다: <대상>(<code>, <reason>) — <경로>" 를 담는다.
- **누가 무엇을**: 내보내기와 검증은 뷰어(rhwp)가 하고, 검증을 통과한 바이트만 서버로 보낸다. 파일 쓰기는 서버가 한다. 같은 폴더의 임시 파일에 다 쓴 뒤
  - 덮어쓰기(`overwrite: true`): 이름을 바꿔 한 번에 바꾼다(원자적 — 쓰다 실패해도 기존 파일이 반쯤 바뀌지 않는다). 기존 파일의 권한을 유지하고, 대상이 심볼릭 링크면 링크는 두고 실제 파일을 바꾼다(임시 파일도 실제 파일 폴더에 — 다른 디스크여도 된다).
  - 덮어쓰지 않기: 배타적으로 만든다(하드 링크, 링크를 못 만드는 파일 시스템이면 덮지 않는 복사 — 복사가 중간에 실패하면 만든 파일을 지운다). 경로를 정한 뒤 같은 이름의 파일이 생겼으면(동시 저장, 다른 프로그램) 덮지 않는다 — 기본 이름이면 다음 번호(`-수정-2` …)로 저장하고, 지정한 경로면 "이미 있는 파일입니다…" 오류.
  - 실패하면 임시 파일을 지운다.
- **뷰어 → 서버 전송**: 열기(서버 → 뷰어)와 같은 base64 JSON(WebSocket 메시지 하나)이다. 크기 상한은 열기와 같은 **50MB**(base64 로 약 67MB, `ws` 메시지 상한 100MB 안). 내보낸 파일이 50MB 를 넘으면 뷰어가 보내지 않고 "저장할 문서가 너무 큽니다(<n>MB). 50MB 까지 저장할 수 있습니다." 를 돌려준다. 서버도 받은 바이트의 크기·길이를 다시 확인한다(맞지 않으면 "뷰어가 보낸 파일이 온전하지 않습니다(…). 다시 저장하세요."). 바이너리 프레임·일회용 HTTP 주소는 v0.2(#8 메모).
- 저장 뒤에도 문서는 열린 채로 계속 고칠 수 있다(되돌리기 기록도 남는다).
- 저장하면 **저장 경로가 "마지막 파일"이 된다**(SPEC-001 의 미연결 오류 " 마지막 파일:" 과 새로고침 때 다시 읽는 파일). 저장 전 검증이 블록 위치까지 같은 것을 확인하므로, 저장한 파일을 다시 읽어도 블록 id 는 그대로다. 서버는 이때의 블록 id 표 사본(기준 표)과 블록 위치를 떠 둔다(새로고침용). "저장하지 않은 편집" 수는 저장 때 0 으로 돌아가고, 뷰어에도 알려 새로고침 확인 창을 끈다.

2. "3번 항목을 1번 위로 올려줘" → Claude 가 `get_outline` 으로 대상 블록을 찾고 `move_blocks` 를 부른다. 뷰어가 다시 그려지고 번호는 1·2·3 으로 다시 매겨지며, 옮긴 문단과 번호가 바뀐 문단에 초록 테두리가 남는다.

### 예외와 경계 상황

- **옮길 수 없는 문단**: 각주·미주, 책갈피, 새 번호로 시작, 머리말·꼬리말, 감추기, 쪽 번호, 차트·OLE 같은 개체, 문단 경계를 넘는 누름틀이 든 문단과 **구역 첫 문단**(구역·단 정의가 든다)은 rhwp 가 블록 복제를 거부한다(목록·확인한 곳은 ADR 002). 거부된 문단마다 "이 문단은 옮길 수 없습니다(<이유>): <블록 id>. 글자만 옮기려면 insert_paragraph 와 delete_blocks 를 쓰세요." 를 모아(한 줄에 하나) 돌려주고 아무것도 바꾸지 않는다(되돌리기 기록에도 남지 않는다). 블록 id 는 그 문단의 블록 중 문서에서 첫 블록이고, 고른 블록 사이의 빈 문단이면 "<앞 블록 id> 뒤 빈 문단" 이다. 일반 하이퍼링크는 옮겨진다.
- **구역 첫 문단 앞**: 구역 첫 문단 앞으로는 옮기지 않는다(구역 정의가 둘째 문단에 남는다). "구역 첫 문단 앞으로는 옮길 수 없습니다. 첫 문단 뒤로 옮기세요."
- **구역 첫 문단 앞에 넣기**: `insert_paragraph` 도 구역 첫 문단 앞에는 넣지 않는다(같은 이유, 저장해 다시 열면 구역 정의가 둘이 된다). "구역 첫 문단 앞에는 문단을 넣을 수 없습니다. 첫 문단 뒤에 넣으세요."
- **다른 구역**: 옮길 블록끼리나 옮길 블록과 기준 블록이 다른 구역이면 v0.1 에서는 "다른 구역으로는 옮길 수 없습니다. 같은 구역 안에서 옮기세요." 로 거부한다.
- **직접 입력한 번호**: "1." 처럼 글자로 친 번호는 옮겨도 바뀌지 않는다. `move_blocks` 결과에 "직접 입력한 번호가 있는 문단: <id 목록>. 번호를 고치려면 replace_text 를 쓰세요." 경고를 담는다. 대상은 옮긴 문단과, 옛 자리와 새 자리 사이에서 순서가 바뀐 문단이다("1. 2. 3." 에서 3 을 맨 위로 옮기면 세 문단 모두). 판정은 문단 블록 글자의 맨 앞(앞 공백은 건너뜀)이 아래 중 하나일 때다(자동 번호 `number` 는 글자가 아니라 보지 않는다).
  - 숫자 1~2자리 + `.` 또는 `)` 뒤에 공백이나 글 끝: `1.` `12)` (`2026. 11.` 같은 날짜는 4자리라 아니다)
  - 한글 가~하 한 글자 + `.` 또는 `)` 뒤에 공백이나 글 끝: `가.` `나)`
  - 괄호 안 숫자 1~2자리나 가~하 한 글자 뒤에 공백이나 글 끝: `(1)` `(가)` (전각 괄호 `（1）` 포함, "(사)한국…협회" 같은 접두는 아니다)
  - 동그라미 숫자·글자 뒤에 공백이나 글 끝: `①`~`⑳`, `㉠`~`㉭`, `㉮`~`㉻` ("①번 항목은…" 같은 문장은 아니다)
  - 로마 숫자 글자(`Ⅰ`~`Ⅻ`, `ⅰ`~`ⅻ`) + `.` 또는 `)` 뒤에 공백이나 글 끝
- **이어지지 않은 블록**: `move_blocks` 의 `ids` 가 문서에서 이어져 있지 않으면(고른 블록이 든 문단 사이에 고르지 않은 블록이 든 문단이 있으면) "옮길 블록이 문서에서 이어져 있지 않습니다. 사이 블록 <id 목록> 도 ids 에 넣거나 따로 옮기세요." 로 거부한다. 기준 블록이 옮길 문단 안에 있으면(고른 블록이거나 같은 문단의 누름틀 등) "기준 블록 <id> 가 옮길 블록 안에 있습니다." 로 거부한다. 같은 id 를 여러 번 주면 한 번으로 본다.
- **이미 그 자리**: 옮길 블록이 블록 순서로 이미 기준 블록 바로 앞(뒤)에 있으면(사이에 블록 없는 빈 문단만 있어도 — 옮겨도 빈 문단 위아래만 바뀐다) 바꿀 것이 없어 "<id 목록> 은 이미 <기준 id> 앞(뒤)에 있습니다. 옮길 것이 없습니다." 로 거부한다.
- **문단 가운데**: 옮기는 단위는 문단이라, 기준 블록 앞(`before`)이나 뒤(`after`)에 같은 문단의 다른 블록이 있으면(문단 글자 뒤의 누름틀·표 등) "기준 블록 <id> 는 다른 블록과 같은 문단(<id 목록>)에 있어 그 사이로는 옮길 수 없습니다. <첫 id> 앞이나 <끝 id> 뒤로 옮기세요." 로 거부한다. "이미 그 자리"는 그다음 블록 순서로 본다.
- **누름틀 블록만 옮기기**: 누름틀은 문단째 옮긴다. 고른 블록이 어떤 문단의 누름틀뿐이고 그 문단에 문단·표 블록이 있으면 "<누름틀 id>: 누름틀 블록만 옮길 수는 없습니다. 누름틀이 든 블록 <id> 를 옮기세요." 로 거부한다(빈 누름틀만 든 문단처럼 누름틀 말고 블록이 없으면 그 누름틀로 문단을 고른다). 표 칸 안 누름틀도 같다(표 블록을 옮긴다).
- **구역 첫 문단 지우기**: `delete_blocks` 는 구역 첫 문단을 지우지 않는다. rhwp 는 첫 문단을 지우면 그 안의 구역·단 정의도 같이 지운다(HWPX 로 저장할 때 다시 만들어 넣지만 편집 중 문서에는 구역 정의가 없다). "구역 첫 문단은 지울 수 없습니다(구역·단 정의가 든 문단): <블록 id>. 글자를 지우려면 replace_text 를 쓰세요." 첫 문단에 든 표는 표만 지운다.
- **구역의 마지막 문단**: rhwp 는 구역에 하나 남은 문단을 지우지 못한다. 구역 첫 문단을 지우지 않으므로 지우기로 구역이 비는 일은 없다 — 구역의 블록을 모두 지우라고 하면 첫 문단에서 거부된다(옮기기는 구역의 문단 수를 바꾸지 않아 해당 없다).
- **누름틀 블록 지우기**: "누름틀 블록은 지울 수 없습니다: <블록 id>. 값을 비우려면 replace_text 를, 문단째 지우려면 그 문단 블록 id 를 주세요." 아무것도 지우지 않는다.
- **블록이 아닌 개체가 든 문단**: 문단째 지울 문단(글자 있는 문단도)에 머리말·꼬리말, 각주·미주, 그림·도형, 수식, 쪽 번호 위치, 감추기처럼 블록이 아닌 개체가 있으면 같이 사라지므로 거부한다. 책갈피·새 번호·번호 넣기·누름틀처럼 문단 글자와 같이 사라지는 보이지 않는 인라인 컨트롤은 막지 않는다. "<블록 id>: 문단에 블록이 아닌 개체(<종류>)가 있어 같이 사라지므로 지울 수 없습니다."
- **누름틀이 든 문단의 표**: rhwp 는 표만 지우면 같은 문단의 누름틀(표 안·표 밖)을 잃는다. 그래서 누름틀이 든 문단에서 표만 지우는 것은 거부한다. 표 안 누름틀만 있고 표만 든 문단이면 문단째 지운다(누름틀 id 도 `deleted` 에). 거부 문구는 "<블록 id>: 누름틀이 든 문단에서는 표만 지울 수 없습니다(표만 지우면 누름틀이 망가집니다)." 뒤에 방법을 붙인다 — 문단 글자가 있으면 "문단째 지우려면 표가 든 문단의 문단 블록 id 를 같이 주세요.", 구역 첫 문단이거나 표 밖 누름틀만 있는 문단이면 "… 문단째 지울 수도 없으므로 이 표는 지울 수 없습니다.".
- **표 안 문단**: v0.2 전에는 표 칸 안 문단을 옮기거나 넣지 않는다(칸 글자는 `replace_text` 로). 칸 안 문단은 블록 id 가 없어 `move_blocks` 로 고를 수 없고, 표 칸 안 누름틀을 고르면 위 "누름틀 블록만 옮기기"로 거부된다.
- **여러 블록에 걸친 replace**: `replace_text` 대상은 블록 하나(또는 칸 하나) 안이어야 한다.
- **되돌릴 것이 없음**: "되돌릴 편집이 없습니다." 20단계를 넘은 옛 편집은 되돌릴 수 없다.
- **편집 기록 어긋남**: 서버와 뷰어는 편집 순번(연 뒤 적용한 편집 수 − 되돌린 수)을 따로 센다. 편집 요청이 타임아웃되거나 결과를 읽지 못하면 뷰어는 적용했는데 서버는 기록하지 못했을 수 있다. 그러면 다음 편집·되돌리기에서 뷰어가 아무것도 하지 않고 "편집 기록이 어긋났습니다(서버 <n>, 뷰어 <m>). open_document 로 문서를 다시 열어 주세요." 를 돌려준다(그대로 두면 되돌리기가 엉뚱한 편집을 되돌린다).
- **새 문서를 열면** 편집 기록과 되돌리기는 사라진다. 저장하지 않은 편집이 있으면 `open_document` 결과 `warnings` 에 "저장하지 않은 편집 <n>개를 버렸습니다" 를 담는다(새 문서를 열지 못해도 이전 문서는 닫히므로 오류 끝에 같은 말을 붙인다). 저장하지 않은 편집 수는 되돌리기 칸과 따로 센다 — 20개를 넘게 고쳐도, 저장한 뒤 되돌려도 마지막으로 열거나 저장한 파일과 다른 편집 수다.
- **새로고침**: 뷰어는 마지막 파일(저장했으면 저장 파일, 아니면 연 파일)을 다시 읽는다(SPEC-001). 저장하지 않은 편집은 사라지고, 서버는 블록 id 표를 그 파일을 열거나 저장했을 때(기준 표)로 되돌리고 되돌리기 기록을 비운다(뷰어도 문서를 새로 열어, 편집 기록 어긋남을 가리는 편집 순번이 서버·뷰어 둘 다 0 에서 다시 시작한다). 사라진 편집이 있으면 다음 도구 결과(성공·오류 모두)에 글 한 덩이로 "뷰어를 새로고침해서 저장하지 않은 편집 <n>개가 사라졌습니다." 를 붙인다(한 번만). 저장하지 않은 편집이 있는 동안 뷰어 탭을 닫거나 새로고침하면 브라우저 확인 창(`beforeunload`)이 뜬다. 저장하지 않은 편집 수는 서버 편집 기록만 세고(저장한 뒤 되돌린 것도 센다), 서버가 편집·되돌리기 요청에는 그 뒤의 값을 실어, 저장 뒤에는 따로 뷰어에 보내 확인 창 여부를 정한다(문구는 브라우저가 정한다. 페이지를 한 번도 누르지 않은 탭에서는 브라우저가 띄우지 않는다). README 에도 알린다.
- **저장 실패**: 쓰기 권한 없음, 디스크 가득 등은 "저장하지 못했습니다: <이유>" 를 돌려주고 문서 상태(마지막 파일, 저장하지 않은 편집 수)는 그대로 둔다.

## 수용 기준

- [x] AC-1 `replace_text` 는 문단 일부·문단 전체·표 칸·누름틀 값을 바꾸고, 바뀐 자리의 글자 모양(첫 글자 기준)을 유지한다 (자동)
- [x] AC-2 `insert_paragraph` 는 기준 블록 앞/뒤에 기준 문단 모양으로 새 문단을 넣고 새 블록 id 를 준다. 기존 블록 id 는 바뀌지 않는다 (자동)
- [x] AC-3 `delete_blocks` 는 문단·표를 지우고, 나머지 블록 id 는 바뀌지 않는다. 누름틀 블록과 구역을 비우는 삭제는 거부한다 (자동)
- [x] AC-4 `move_blocks` 는 이어진 블록을 서식째 옮기고 블록 id 를 유지하며, 자동 번호 문단은 옮긴 뒤 번호가 새 순서로 다시 매겨진다 (자동)
- [x] AC-5 옮길 수 없는 문단(각주·책갈피 등. 일반 하이퍼링크는 옮겨진다)이 있으면 아무것도 바꾸지 않고 이유와 블록 id 를 돌려준다 (자동)
- [x] AC-6 직접 입력한 번호가 있는 문단을 옮기면 결과에 경고를 담는다 (자동)
- [x] AC-7 편집 뒤 뷰어가 다시 그려지고 바뀐 블록에 표시가 남으며, 다음 편집·하이라이트 때 지워진다 (자동)
- [x] AC-8 `undo` 는 편집을 하나씩(최대 20단계) 되돌리고 블록 id 표도 그때 상태로 돌아간다. 되돌릴 것이 없으면 정해진 문구를 돌려준다 (자동)
- [x] AC-9 `save_document` 는 경로가 없으면 원본 옆 `<이름>-수정.hwpx`(겹치면 번호)로 저장하고, 원본·기존 파일은 `overwrite: true` 일 때만(원본은 `.hwpx` 일 때만) 덮어쓴다 (자동)

## 기술 검증 (첫 이슈)

기능 이슈 전에 확인하고 결과로 이 스펙과 ADR 을 고친다. **결과(#18): GO** (rhwp 다시 열기 비교 + 맥 한컴 뷰어에서 경고 없이 열림, 2026-10-27) — 방식·측정값·NO-GO 일 때 대안은 `docs/decisions/002-edit-and-save.md`. 한글 확인용 파일은 `node scripts/make-hwp-check.ts` 로 만든다(`~/Downloads/docbridge-hwp-check/`, 레포에 넣지 않음).

- `importParagraphBlock` + `deleteParagraph` 로 같은 문서 안에서 이어진 문단 여러 개를 옮길 수 있는지: 문단 모양·글자 모양·자동 번호 유지, 거부되는 컨트롤 목록, 같은 문서를 원본으로 쓸 때(내보내 다시 연 사본이 필요한지) 비용.
- `replaceText` / 칸 글자 바꾸기(`replaceTextInCell…`) / `setFieldValue` 가 글자 모양을 유지하는지.
- `insertParagraph` 뒤 기준 문단 모양 복사가 되는지, 빈 문단에 글자를 넣는 방법.
- `saveSnapshot`/`restoreSnapshot` 으로 20단계 되돌리기가 되는지(메모리), 블록 id 표를 같이 되돌리는 방법.
- `exportHwpxWithReport` 의 보고서 형식과, 내보낸 HWPX 를 다시 열어 비교하는 비용.
- 위 편집을 한 fixture 를 HWPX 로 저장해 **한글 프로그램에서 열어 본다**(수동, 맥 한글 또는 한글 Viewer). 손상·변조 경고가 나면 원인과 대안(원본 ZIP 최소 패치 등)을 정리한다.

GO 기준: 이동·바꾸기·칸 채우기를 한 fixture 3개가 한글에서 경고 없이 열리고 내용·번호가 맞다.

## 기술 메모

- 근거: `docs/research/rhwp-code-analysis.md` 2장(문단 이동 절차: 스냅샷 → 사본 → `importParagraphBlock` dryRun → 실행 → 원본 `deleteParagraph`(인덱스 보정) → 검증 → 실패 시 `restoreSnapshot`, 붙여넣기는 문단 모양을 바꾸므로 쓰지 않음, 거부 컨트롤 목록), `docs/research/rhwp-issues-analysis.md`(저장 후 한컴 손상 경고 73건 — 저장 검증과 수동 QA 필수).
- 편집은 뷰어(rhwp)에서 하고, 서버는 블록 id 표를 편집에 맞춰 옮긴다(삽입·삭제·이동). 되돌리기 때 id 표도 스냅샷과 함께 되돌린다.
- 블록 캐시(PR #12 리뷰에서 넘어온 것): 서버에 두지 않는다. 뷰어가 편집이 끝날 때마다 블록을 다시 뽑아 들고(74쪽 문서 54ms), 서버는 지금처럼 도구마다 뷰어에서 받는다(같은 문서 JSON 387KB). 번호가 다시 매겨지는 편집은 바뀐 블록이 편집 대상 밖까지 번져 "바뀐 블록만 갱신"이 틀리기 쉽다(ADR 002).
- 편집 절차(`src/core/edits.ts`, ADR 002): 옮기기 = HWP 사본(거부되면 HWPX 사본) → `importParagraphBlock` dryRun → 실행 → 원본 지우기(인덱스 보정) → 옮긴 문단의 문단 모양 id 되돌리기(안 하면 번호가 1부터 다시 시작). 글자 바꾸기 = 첫 글자 뒤에 넣고 나머지·첫 글자 지우기(rhwp `replaceText`·`setFieldValue` 는 앞 글자 모양을 따라 쓰지 않음, 빈 누름틀만 `setFieldValue`). 칸은 경로 API(`insertTextInCellByPath` 등)와 `deleteRangeInCell`. 누름틀은 이름이 겹칠 수 있어 `fieldId` 로 고른다(누름틀 블록에 `fieldId` 필요). 새 문단 = `insertParagraph` + 기준 문단 모양 `setParaShapeId`.
- 되돌리기: 편집마다 뷰어가 `saveSnapshot` 하나, 서버가 편집 전 블록 id 표 사본(`BlockIdTable.clone`) 하나를 같은 순서로 쌓는다. 20칸을 넘으면 가장 옛 스냅샷을 `discardSnapshot`. 74쪽 문서 스냅샷 20개 34ms·42.9MB(하나 약 2MB).
- 저장 검증: `exportHwpxWithReport` 의 손실 보고(`{count, losses:[{code, subject, path, reason}]}`)는 경고로, 다시 열어 블록(위치·글자·번호·칸·누름틀 값) 비교(`src/core/hwpx-export.ts`). 74쪽 문서에서 약 460ms.
- 바뀐 블록 표시 색은 `src/viewer/tokens.css` 에 토큰으로, `docs/design.md` 에 역할과 이유.

## 열린 질문

- ~~새로고침하면 저장하지 않은 편집이 사라지는 문제~~ → 사라지게 두고 알린다(마지막 파일 다시 읽기, id 표·되돌리기 기록 되돌림, 다음 도구 결과에 사라진 편집 수, 브라우저 확인 창). 편집마다 문서를 서버에 보내 두는 안은 74쪽 문서에서 편집마다 246ms·4.5MB 라 하지 않는다 (#18, ADR 002)
- ~~저장 후 "마지막 파일"을 저장 경로로 바꿀지~~ → 바꾼다. 저장 검증이 블록 위치까지 같은 것을 확인해 id 표를 그대로 쓴다 (#18)
- ~~블록 캐시를 서버에 둘지~~ → 두지 않는다. 뷰어가 편집마다 다시 뽑고 서버는 도구마다 받는다 (#18)
- ~~바뀐 블록 표시 모양~~ → 블록 전체를 쪽마다 감싸는 2px 초록 테두리(개인 DS success, 비텍스트 대비 3:1 이상, 블록 밖 2px). 노랑 하이라이트와 겹쳐도 뜻이 갈리고 글자를 덮지 않는다. 시안 비교 생략 — 색은 스펙에서 초록으로 정했고 모양은 근거 하이라이트(면)와 겹치지 않는 테두리 하나 (#19, `docs/design.md`)
