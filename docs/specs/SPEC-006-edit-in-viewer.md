# SPEC-006 뷰어에서 직접 고치기

## 배경과 목표

지금 뷰어는 보기 전용이다(PRD 열린 질문 "사람이 뷰어에서 직접 편집하게 할지 — v0.1 사용 후"). v0.1 을 써 보니 Claude 가 고친 결과에서 한 단어만 다듬거나, 문단 하나를 지우고 옮기는 일도 채팅으로 말해야 해서 번거롭다. 배포(SPEC-004)해서 다른 사람이 쓰면 가장 먼저 나올 요구다.

이 스펙이 끝나면:
- 문단(표 칸)을 더블클릭해 글자를 바로 고칠 수 있다.
- 문단을 끌어서 옮기고, 오른쪽 클릭으로 지우기·위로·아래로를 할 수 있다.
- 사람이 고친 것도 Claude 가 고친 것과 **같은 편집 경로**를 탄다. 블록 id 가 어긋나지 않고, 되돌리기 한 줄에 같이 쌓이고, 초록 표시가 남고, Claude 는 다음 읽기에서 바뀐 내용을 그대로 본다.

## 동작 정의

### 원칙

- **편집기를 새로 만들지 않는다.** 사람 편집은 기존 편집 종류(`replace_text`·`delete_blocks`·`move_blocks`)를 뷰어에서 부르는 것이다. 커서·한 글자 입력·서식 도구 막대가 있는 진짜 편집기(`@rhwp/editor`)는 이 스펙 밖이다(ADR 001 유지).
- **편집은 서버를 거친다.** 뷰어는 바로 고치지 않고 서버에 "이 편집을 해 달라"고 보낸다. 서버가 Claude 편집과 같은 직렬 큐·id 표·편집 기록으로 처리한다(문서 상태의 기준은 여전히 브라우저, id 표는 서버).

### 글자 고치기

1. 문단(또는 표 칸)을 더블클릭하면 그 블록 위에 입력칸이 뜬다. 처음 글자는 블록(칸) 글자 전체, 커서는 더블클릭한 자리. 더블클릭한 점이 블록 자리(바뀐 블록 테두리와 같은 문단 글자 사각형, 표는 칸 사각형, 빈 문단은 커서 줄의 단 폭) 안일 때만 뜬다 — rhwp `hitTest` 는 빈 곳에도 가까운 문단을 주기 때문이다.
2. Enter 또는 바깥 클릭(입력칸 밖을 누름)이면 적용, Esc 면 취소. 글자가 같으면 편집하지 않는다. 한글 조합 중 Enter 는 조합을 끝낼 뿐 적용하지 않는다. 다른 창으로 옮겨 가 포커스만 잃은 것은 적용하지 않는다.
3. 적용은 `replace_text`(블록 글자 전체 대상)와 같다. 글자 모양은 기존 규칙(바뀌는 자리 첫 글자 모양). 다만 **바뀐 부분만** 바꾼다 — 앞뒤 같은 글자는 건드리지 않아 굵게 등 부분 서식이 남는다(입력 전후를 비교해 바뀐 범위를 구한다). 같은 글자가 이어지는 곳("가가나" 에서 "가" 하나 지우기)은 적용 직전 입력칸 커서로 사람이 고친 쪽을 정한다 — 고친 글자가 커서 바로 앞에서 끝난다고 본다(누름틀 값 안/밖, 부분 서식이 갈린다).
4. 입력칸에서 줄바꿈은 받지 않는다(Shift+Enter 무시, 붙여 넣은 글자의 줄바꿈은 빈칸). 문단 나누기는 범위 밖. 칸 안 여러 문단은 입력칸에 줄로 보이고, 문단 사이를 지우면 문단이 합쳐진다(`replace_text` 칸 규칙).
5. 누름틀은 값을 고친다(`replace_text` 누름틀 규칙): 누름틀 값(빈 누름틀은 빨간 안내문) 위를 더블클릭하면 값만 든 입력칸이 뜬다. 글상자·각주·머리말·표 안 표는 더블클릭해도 반응 없음.
6. 문단(칸) 입력칸에서 바뀐 범위가 그 안 누름틀 값에 걸칠 때(서버 `replace_text` 는 걸친 문단 범위를 거부한다, #69): 바뀐 범위가 **값 안에만** 있으면 그 누름틀 값 편집으로 보낸다. 값과 그 바깥에 같이 걸치면 보내지 않고 "누름틀 값과 그 바깥 글자를 한 번에 고칠 수 없습니다. 누름틀 값은 값 위를 더블클릭해 따로 고치세요." 를 보여 준다. 값 바로 앞·뒤에 넣는 것은 값 밖 문단 글자다(서버 걸침 판정과 같다).
7. 뷰어가 서버에 보내지 않은 거부(6, 아래 "입력칸이 열린 동안"), 서버 거부, 연결 끊김은 모두 뷰어 아래 알림(아래 "화면")으로 보이고 입력칸은 닫힌다.

### 옮기기·지우기

- 문단을 끌어서 다른 문단 사이에 놓으면 `move_blocks`(놓은 자리 기준 `before`/`after`). 끄는 동안 놓일 자리에 가로선이 보인다.
- 오른쪽 클릭 메뉴: **지우기**(`delete_blocks`), **위로**·**아래로**(바로 앞·뒤 블록 기준 `move_blocks`).
- `move_blocks`·`delete_blocks` 의 거부 규칙(구역 첫 문단, 쪽 번호 위치 컨트롤 등)은 그대로 — 거부되면 뷰어 아래쪽에 문구를 3초 보여 주고 아무것도 바꾸지 않는다.
- 표는 블록째 옮기기·지우기만 된다(칸 안 끌기 없음).

### Claude 와 함께 쓸 때

- 사람 편집과 Claude 편집은 **같은 되돌리기 줄**에 쌓인다. Claude 의 `undo` 는 마지막 편집이 사람 것이어도 그것을 되돌린다(채팅에서 "되돌려"는 "방금 화면에서 바뀐 것"이 자연스럽다). 뷰어에서는 ⌘Z(윈도우 Ctrl+Z)로 같은 `undo` 를 부른다(한 번에 하나, 마지막 편집이 Claude 것이어도).
- 편집 기록 이름에 출처를 남긴다: 사람 편집은 `replace_text b11 (사용자 화면 편집)` 처럼 붙어, Claude 의 `undo` 결과 `edits` 에서 가려진다.
- 되돌릴 편집이 없을 때 ⌘Z 를 누르면 상태 줄에 "되돌릴 편집이 없습니다." 를 보여 주고 아무것도 바꾸지 않는다. 연결이 끊겨 있으면 "docbridge 와 연결이 끊겨 고칠 수 없습니다".
- 사람 편집 뒤 Claude 가 `get_outline`·`read_blocks` 를 부르면 고친 글자가 보인다(서버 블록이 이미 최신).
- 뷰어는 보고 있는 문서의 상태 번호(서버가 편집·되돌리기 요청에 실어 보낸 "그 뒤의 번호", 같은 번호 = 같은 문서)를 같이 보낸다. 서버 줄에서 차례가 왔을 때 번호가 다르면(그사이 Claude 편집·되돌리기가 먼저 처리돼 블록 위치가 어긋났을 수 있음) 적용하지 않고 "그사이 문서가 바뀌어 적용하지 못했습니다. 다시 고쳐 주세요." 로 거부한다. 편집 순번(depth)이 아니라 상태 번호인 것은 되돌린 뒤 다른 편집을 하면 순번은 같아도 문서가 다르기 때문이다. 뷰어가 Claude 편집을 적용한 뒤(서버 기록 전) 보낸 사람 편집은 그 기록 뒤에 차례가 와 번호가 맞으므로 적용한다(replace_all 의 "읽은 뒤 다른 편집이 끼면 거부" 와 같은 판정, SPEC-005). 상태 번호는 문서를 열 때마다 0 부터라, 요청을 받은 뒤 그 탭의 문서가 바뀌었으면(같은 파일 `open_document` 다시 열기·새로고침) 번호와 상관없이 같은 문구로 거부한다 — 이전 문서 화면에서 보낸 편집·⌘Z 가 다시 연 문서에 쓰이지 않는다. 사람 편집은 그 탭 문서(SPEC-007 `doc`)의 줄·편집 기록으로 가므로, 다른 문서를 열거나 만들거나 고친 것은 이 문서의 번호를 바꾸지 않아 거부 사유가 아니다.
- 사람이 편집하는 동안(입력칸이 열려 있는 동안) Claude 편집이 오면, Claude 편집을 먼저 처리하고 입력칸은 닫지 않는다(문단 넣기·지우기·옮기기면 입력칸 블록 위치를 따라 옮기고, 입력칸도 다시 그린 쪽의 그 블록 새 자리로 옮긴다). 사람이 적용할 때 그 블록(칸·누름틀) 글자가 입력칸을 열 때와 다르면 보내지 않고 "그사이 이 문단이 바뀌어 적용하지 못했습니다. 다시 고쳐 주세요." 를 보여 준다(뷰어가 판단한다 — 서버가 그 Claude 편집을 아직 기록하기 전이어도 같다. 문구에 주체를 적지 않는 것은 방금 적용한 내 편집이 응답 전에 돌아와도 같은 판정이기 때문). 그 문단이 지워졌거나 되돌리기가 오거나 블록 자리를 찾지 못하면(쪽이 사라짐 등) 입력칸을 둘 곳이 없어 그때 바로 닫고, 고친 것이 있으면 같은 문구를 보여 준다. 고친 것이 없으면 문구 없이 닫는다.
- 응답이 늦을 때(PR #71 리뷰 — 서버 줄이 밀리면 뷰어는 기다리다 그만뒀는데 서버가 나중에 적용할 수 있다): 서버는 사람 편집·⌘Z 를 받은 뒤 줄 차례가 20초(`USER_REQUEST_DEADLINE_MS`) 넘게 늦게 오면 적용하지 않고 "docbridge 가 앞선 작업을 처리하느라 늦어져 적용하지 않았습니다. 다시 고쳐 주세요." 로 거부한다. 뷰어는 30초(`REQUEST_TIMEOUT_MS`) 기다리고, 넘으면 "docbridge 가 30초 안에 답하지 않았습니다. 화면이 바뀌지 않았으면 다시 해 주세요." 를 보여 준다. 서버 마감이 뷰어 기다림보다 짧아 뷰어가 실패를 보인 편집은 나중에 적용되지 않는다. 마감 전에 적용을 시작한 드문 경우에는 그 편집 요청으로 화면이 다시 그려지므로 화면이 기준이다(문구도 화면을 보라고 한다).
- Claude 에게 사람 편집을 알린다: 다음 도구 결과에 `notices`(예: "사용자가 화면에서 고침: b11 글자, b6 옮김") 를 한 번 붙인다(SPEC-002 새로고침 알림과 같은 자리). 지난 도구 결과 뒤 사람이 한 일을 한 줄로 묶는다 — 글자 고침 `b11 글자`, 옮김 `b6 옮김`, 지움 `b4 지움`(여러 블록은 `b6·b7`), ⌘Z `되돌림(<편집 이름>)`. 그 탭의 문서가 바뀌면(같은 파일 다시 열기·새로고침·닫기) 그 문서의 사람 편집 알림은 버린다(다시 연 문서의 블록 id 와 헷갈리지 않게, 버린 편집은 기존 "편집 N개를 버렸습니다"·"사라졌습니다" 알림이 알린다). 지우기에 같은 블록이 두 번 와도 한 번만 지운다(Claude `delete_blocks` 와 같게).
- 서버는 요청을 받는 뷰어(그 문서 이름으로 마지막에 붙은 탭, SPEC-007)의 사람 편집만 받는다. 같은 문서의 이전 탭이나 문서가 없는 빈 탭(close_document 로 닫은 문서의 탭 포함)이면 "다른 뷰어 탭이 이 문서로 docbridge 에 붙어 있어 이 탭에서는 고칠 수 없습니다. 마지막에 연 탭에서 고치세요." 다른 문서의 알림은 Claude 결과에 문서 이름을 앞에 붙여 알린다("d1: 사용자가 화면에서 고침: …").

### 화면

- 블록에 마우스를 올리면 옅은 테두리(편집할 수 있는 블록이 무엇인지). 표는 칸 단위, 누름틀은 값(빈 누름틀은 안내문) 자리. 입력칸이 열려 있으면 그리지 않는다.
- 입력칸 글꼴·크기는 문서와 같지 않아도 된다(뷰어 UI 글꼴, `tokens.css`). 블록 자리에 뜨고 짧은 블록도 최소 폭이 있다. 적용하면 문서 모양으로 다시 그려진다.
- 하이라이트·note 가 있는 블록도 더블클릭으로 고칠 수 있다(하이라이트·note 는 마우스를 막지 않는다). 고치면 그 블록 하이라이트는 지운다 — 편집은 쪽을 다시 그려 하이라이트·note 를 모두 지운다(SPEC-002 "편집과 하이라이트는 같이 보이지 않는다").
- 실패 문구는 뷰어 아래 가운데 알림(토스트)으로 3초 보인다. 한 번에 하나만 — 새 문구가 오면 바꿔 끼우고 시간을 다시 센다. 같은 문구가 다시 와도 화면 읽기 도구가 다시 읽는다(알림 칸을 숨기지 않고 문구만 새로 넣는다). 끌어 옮기기·오른쪽 클릭(#60)의 거부 문구도 같은 알림을 쓴다. ⌘Z 가 안 된 이유는 지금처럼 상태 줄.
- 서버가 연 문서에서만 고칠 수 있다(개발용 `?fixture=` 화면은 보기만).

### 예외와 경계 상황

- 뷰어가 서버와 끊겨 있으면 편집하지 않고 "docbridge 와 연결이 끊겨 고칠 수 없습니다" 를 보여 준다.
- 새로고침 확인 창·저장하지 않은 편집 수는 사람 편집도 센다.
- 빈 문단 블록(새 문서 첫 블록, 글자를 모두 지운 문단)도 더블클릭으로 채울 수 있다. 처음 열 때부터 빈 문단은 블록이 아니라(get_outline 에 없음, SPEC-001) 반응 없다.

## 수용 기준

- [ ] AC-1 문단을 더블클릭해 글자를 고치고 Enter 하면 바뀌고, 앞뒤 같은 글자의 부분 서식(굵게)이 남는다 (자동 — E2E)
- [ ] AC-2 Esc·같은 글자면 편집이 생기지 않는다(undo 칸·저장 안 한 편집 수 그대로) (자동)
- [ ] AC-3 표 칸·누름틀 값을 더블클릭해 고칠 수 있다 (자동 — E2E)
- [ ] AC-4 문단을 끌어 놓으면 옮겨지고 번호가 다시 매겨진다 (자동 — E2E)
- [ ] AC-5 오른쪽 클릭 지우기·위로·아래로가 되고, 거부되는 블록은 문구만 보이고 바뀌지 않는다 (자동 — E2E)
- [ ] AC-6 사람 편집 뒤 `read_blocks` 가 고친 글자를, `get_outline` 이 옮긴 순서를 돌려주고 기존 블록 id 는 그대로다 (자동)
- [ ] AC-7 사람 편집과 Claude 편집이 한 되돌리기 줄에 쌓이고, ⌘Z 와 `undo` 가 같은 줄을 되돌린다 (자동)
- [ ] AC-8 입력칸이 열린 동안 Claude 가 같은 블록을 바꾸면 사람 적용은 거부되고 문구가 보인다 (자동)
- [ ] AC-9 사람 편집 뒤 다음 도구 결과에 `notices` 로 한 번 알린다 (자동)
- [ ] AC-10 실제 공문에서 Claude 가 고친 문단을 화면에서 한 단어 고치고 저장한 파일이 한글에서 열린다 (수동 QA)

## 범위 밖

- 커서 이동·한 글자 입력·서식(굵게·크기·색) 바꾸기 — 진짜 편집기(`@rhwp/editor`), 필요하면 다음 스펙에서 ADR 001 다시 결정
- 문단 나누기·합치기(Enter 로 새 문단)
- 새 문단·표 넣기 UI (채팅으로)
- 복사·붙여넣기

## 기술 메모

- 블록 찾기: rhwp `hitTest`(좌표 → 문단·글자 위치, 표 칸이면 칸 경로)로 더블클릭 자리 블록과 커서 위치를 얻고, 블록 위치는 뷰어가 가진 마지막 블록 목록에서 찾는다(`src/core/edit-spot.ts`: `blockAtHit` = 점 → 본문 블록(#60 도 쓴다), `editSpotAt` = 점 → 고칠 자리와 테두리, `replaceEditAt` = 입력칸 글자 → 사람 편집, `followEdit` = 입력칸이 열린 동안 블록 위치 따라가기). `hitTest` 는 누름틀 값 위인지 알려 주지 않을 때가 있어(값이 있는 누름틀) 누름틀 값 사각형으로 가린다.
- 프로토콜: 지금은 서버 → 뷰어 요청만 있다(`src/shared/protocol.ts`). 뷰어 → 서버 요청(`user_request`: `user_edit` = 편집 종류 + 대상 블록 위치(anchor) + 문서 상태 번호, `user_undo` = ⌘Z)과 서버 응답(`user_response`)을 더한다. 뷰어는 블록 id 를 모르므로 블록 위치로 보내고, 서버가 id 표로 id 로 바꾼다(`src/server/user-edit.ts`). 서버는 받은 편집을 `session.edit` 직렬 큐에 넣고, 이후는 Claude 편집과 같다(거부 규칙 포함). 상태 번호를 위해 서버 → 뷰어 `edit`·`undo`·`edit_state` 요청에 `state`(그 요청 뒤의 번호)를 더한다.
- 바뀐 범위만 바꾸기: 앞뒤 공통 글자를 잘라 `{ start, end, text }` 로 만든다(코드포인트 단위, `chars.ts` `changedRange`). 입력칸 커서를 주면 뒤쪽을 커서까지 먼저 맞추고 앞쪽은 남은 만큼만 맞춘 뒤, 커서를 옮겨 남은 뒤쪽은 마저 맞춘다(어떻게 나눠도 결과 글자는 같고 자리만 사람이 고친 쪽으로).
- 편집 출처(`user`/`claude`)를 편집 기록에 남겨 `notices` 를 만든다.
