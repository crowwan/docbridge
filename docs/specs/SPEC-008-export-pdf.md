# SPEC-008 PDF 로 내보내기

## 배경과 목표

docbridge 사용 흐름은 "받아서 열기 → 조금 고치기 → 다시 보내기"다(PRD, rhwp 확장 리뷰 분석). 고친 한글 문서를 돌려보낼 때 받는 쪽이 한글 프로그램이 없거나, 제출처가 PDF 를 요구하는 경우가 많다. 지금은 HWPX 로만 저장할 수 있어서, 사용자가 한글 프로그램이나 다른 변환기로 PDF 를 따로 만들어야 한다.

이 스펙이 끝나면:
- 채팅에서 "PDF 로도 저장해줘" 라고 하면 지금 화면(뷰어)에 보이는 그대로 PDF 파일이 만들어진다.
- 한컴 프로그램·외부 서비스 없이 내 컴퓨터 안에서 끝난다(문서가 밖으로 나가지 않는다).

## 동작 정의

### MCP 도구

| 도구 | 입력 | 결과 |
|---|---|---|
| `export_pdf` | `doc`(선택), `path`(선택), `pages`(선택, 예: `"1-3,5"`) | 문서를 PDF 로 저장한다. 결과 `{ doc, path, pageCount, bytes, warnings? }` |

- `path` 규칙은 `save_document` 와 같다: 없으면 문서 옆에 `<이름>.pdf`(겹치면 `<이름>-2.pdf` …, 배타 생성), 상대 경로는 원본 폴더 기준(새 문서는 `create_document` path 폴더), 확장자가 없으면 `.pdf`, 다른 확장자는 거부. 이미 있는 파일은 `overwrite: true` 일 때만 덮는다.
- 내보내기는 **편집이 아니다**: 되돌리기 칸·저장하지 않은 편집 수에 들어가지 않는다. 저장하지 않은 편집이 있어도 지금 화면 그대로 내보낸다(HWPX 저장과 별개). 결과 `warnings` 에 "저장하지 않은 편집 n개가 PDF 에 들어갔습니다(HWPX 는 아직 저장 전)" 를 붙인다.
- 하이라이트·note·초록 바뀐 블록 표시·마우스 올림 테두리는 PDF 에 **넣지 않는다**(문서 내용만).
- `pages` 를 주면 그 쪽만. 범위가 문서 쪽 수를 넘으면 거부.

### 화면

- 뷰어 도구 막대에 "PDF" 버튼(사람도 바로 내보낼 수 있게). 누르면 같은 규칙의 기본 경로로 저장하고 토스트로 경로를 알린다(SPEC-006 토스트 재사용). 다른 경로를 고르는 대화 상자는 두지 않는다(브라우저가 로컬 경로를 못 고름 — 경로는 채팅으로).

### 품질

- 글자는 PDF 안에서 **선택·검색 가능한 글자**여야 한다(그림으로 찍지 않는다). 기술 검증에서 안 되면 열린 질문으로 되돌린다.
- 글꼴: 문서 글꼴이 이 컴퓨터에 있으면 그 글꼴, 없으면 뷰어가 쓰는 대체 글꼴 — 화면과 같은 글꼴이 PDF 에 들어간다(임베드). 
- 쪽 크기·여백은 문서 쪽 설정 그대로(A4 등).

### 예외와 경계 상황

- 뷰어가 연결되지 않았으면 기존 "뷰어가 없습니다" 오류.
- 아주 큰 문서(수백 쪽)는 시간이 걸린다: 30초 넘으면 진행 중이라고 알리고 계속(타임아웃은 기술 검증 측정 후 결정).
- 이미 있는 파일을 덮을 때 `.hwp`/`.hwpx` 경로를 주면 거부(PDF 로 원본을 덮지 않게).

## 수용 기준

- [ ] AC-1 `export_pdf` 가 기본 경로에 PDF 를 만들고, 결과 쪽 수가 문서 쪽 수와 같다 (자동)
- [ ] AC-2 PDF 안 글자를 추출하면 문서 본문 글자가 나온다(선택·검색 가능) (자동)
- [ ] AC-3 하이라이트·note·바뀐 블록 표시가 PDF 에 들어가지 않는다 (자동)
- [ ] AC-4 `pages` 로 일부 쪽만, 범위 밖은 거부 (자동)
- [ ] AC-5 경로 규칙(기본 이름·겹침·상대 경로·확장자·덮어쓰기·원본 확장자 거부)이 save_document 와 같다 (자동)
- [ ] AC-6 내보내기가 되돌리기 칸·저장하지 않은 편집 수를 바꾸지 않고, 저장 전 편집이 있으면 warnings 로 알린다 (자동)
- [ ] AC-7 뷰어 "PDF" 버튼으로 기본 경로에 저장되고 토스트로 경로를 알린다 (자동 — E2E)
- [ ] AC-8 실제 공문·공고문 PDF 가 macOS 미리보기에서 화면과 같은 모양(표·글꼴·쪽 나눔)으로 보인다 (수동 QA)

## 범위 밖

- PDF → HWP 변환(가져오기)
- 인쇄 대화 상자 띄우기, 프린터로 바로 인쇄
- PDF 에 하이라이트·주석 넣기
- 암호 걸린 PDF, PDF/A

## 기술 메모

- rhwp 에 `renderPageSvg(page)`·`renderPageHtml` 가 있다. 후보:
  1. **뷰어에서 쪽마다 SVG → PDF 라이브러리**(예: jsPDF + svg2pdf.js, 또는 pdf-lib)로 조립해 바이트를 서버로 보내 파일로 쓴다. 글자가 PDF 텍스트로 남는지, 한글 글꼴 임베드(용량·서브셋)가 관건.
  2. **서버에서 헤드리스 브라우저 인쇄**(Playwright `page.pdf`) — 품질은 좋지만 배포판(.mcpb)에 브라우저를 넣을 수 없어 탈락 후보.
  3. 뷰어 `window.print()` + 인쇄 CSS — 사람이 대화 상자에서 PDF 저장을 골라야 해서 Claude 도구로는 안 됨(화면 버튼 보조로만).
- 기술 검증(이슈 하나): 1번으로 fixture 5개 + 실제 공고문을 내보내 글자 추출·글꼴·쪽 크기·시간·파일 크기를 재고 ADR 005 로 결정.
- 저장 경로 규칙은 `save-path.ts` 를 재사용(확장자만 `.pdf`).

## 열린 질문

- PDF 라이브러리와 글꼴 임베드 방식 — 결정: 기술 검증 후
- 시스템 글꼴을 읽을 수 없는 브라우저 환경에서 한글 글꼴을 어디서 얻을지(뷰어 번들에 넣으면 .mcpb 크기 증가) — 결정: 기술 검증 후
