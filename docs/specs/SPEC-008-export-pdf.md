# SPEC-008 PDF 로 내보내기

## 배경과 목표

docbridge 사용 흐름은 "받아서 열기 → 조금 고치기 → 다시 보내기"다(PRD, rhwp 확장 리뷰 분석). 고친 한글 문서를 돌려보낼 때 받는 쪽이 한글 프로그램이 없거나, 제출처가 PDF 를 요구하는 경우가 많다. 지금은 HWPX 로만 저장할 수 있어서, 사용자가 한글 프로그램이나 다른 변환기로 PDF 를 따로 만들어야 한다.

이 스펙이 끝나면:
- 채팅에서 "PDF 로도 저장해줘" 라고 하면 지금 화면(뷰어)에 보이는 그대로 PDF 파일이 만들어진다.
- 한컴 프로그램·외부 서비스 없이 내 컴퓨터 안에서 끝난다(문서가 밖으로 나가지 않는다).

## 동작 정의

### MCP 도구

| 도구 | 입력 | 결과 |
|---|---|---|
| `export_pdf` | `doc`(선택), `path`(선택), `pages`(선택, 예: `"1-3,5"`), `overwrite`(선택) | 문서를 PDF 로 저장한다. 결과 `{ doc, path, pageCount, bytes, warnings? }` |

- `path` 규칙은 `save_document` 와 같다: 없으면 문서(마지막 파일 — 저장했으면 저장한 파일, 저장 전 새 문서는 `create_document` path) 옆에 `<이름>.pdf`(겹치면 `<이름>-2.pdf` …, 배타 생성 — 그사이 생기면 다음 번호, 경로가 없으면 `overwrite` 는 쓰이지 않는다), 상대 경로는 원본 폴더 기준(새 문서는 `create_document` path 폴더), `~/` 는 홈, 확장자가 없으면 `.pdf`, 다른 확장자는 거부. `.hwp`/`.hwpx` 경로(그것을 가리키는 링크 포함)는 `overwrite` 여도 거부(PDF 로 한글 문서를 덮지 않게 — 그래서 열린 다른 문서·저장 중인 파일과 겹치지 않는다). 이미 있는 파일은 `overwrite: true` 일 때만 덮는다(임시 파일 → 이름 바꾸기).
- 내보내기는 **편집이 아니다**: 되돌리기 칸·저장하지 않은 편집 수에 들어가지 않는다. 저장하지 않은 편집이 있어도 지금 화면 그대로 내보낸다(HWPX 저장과 별개). 결과 `warnings` 에 "저장하지 않은 편집 n개가 PDF 에 들어갔습니다(HWPX 는 아직 저장 전)" 를 붙인다.
- 하이라이트·note·초록 바뀐 블록 표시·마우스 올림 테두리는 PDF 에 **넣지 않는다**(문서 내용만).
- `pages` 를 주면 그 쪽만(1부터, 쉼표·범위 `"1-3,5"`, 겹치면 한 번, 오름차순). 범위가 문서 쪽 수를 넘거나 모양이 틀리면 뷰어에 묻기 전에 거부.

### 화면

- 뷰어 도구 막대에 "PDF" 버튼(사람도 바로 내보낼 수 있게). 누르면 같은 규칙의 기본 경로로 저장하고 토스트로 경로를 알린다(SPEC-006 토스트 재사용). 다른 경로를 고르는 대화 상자는 두지 않는다(브라우저가 로컬 경로를 못 고름 — 경로는 채팅으로).

### 품질

- 글자는 PDF 안에서 **선택·검색 가능한 글자**여야 한다(그림으로 찍지 않는다). 기술 검증에서 안 되면 열린 질문으로 되돌린다.
- 글꼴: 문서 글꼴이 이 컴퓨터에 있으면 그 글꼴, 없으면 뷰어가 쓰는 대체 글꼴 — 화면과 같은 글꼴(브라우저와 같은 차례로 고른 이 컴퓨터의 글꼴)의 **글자 모양(윤곽)** 이 PDF 에 들어간다. 선택·검색·복사는 문서 글자(빈칸 포함)를 글자 자리에 맞춰 얹은 **보이지 않는 글자 층**이 맡는다(ADR 005 — PDF 글꼴 글자로 넣으면 미리보기가 맥 고딕 글꼴을 못 읽고 글자 사이에 빈칸을 넣어 검색이 깨진다). 그래서 PDF 글꼴 목록에는 글자 층 글꼴만 보인다.
- 화면과 같은 글꼴: 뷰어가 SVG 글꼴 차례마다 브라우저가 실제로 쓰는 글꼴 이름을 Canvas 글자 폭으로 재서 보내고, 서버는 그 이름을 차례 맨 앞에 두고 고른다. 서버 글꼴에 그 이름이 없으면(폴더를 못 찾음·넣지 말라는 글꼴) 다른 글꼴로 그리고 `warnings` 로 알린다.
- 그러데이션은 첫 색으로, 무늬 채우기·그림자·화살표 끝·PNG/JPEG 가 아닌 그림은 그리지 않고 결과 `warnings` 로 알린다(ADR 005). 그 글자가 든 글꼴이 이 컴퓨터에 하나도 없으면(글꼴 없는 리눅스 등) 그 글자는 보이지 않고 `warnings` 로 알린다(글자 층에는 있어 선택·검색은 된다).
- 쪽 크기·여백은 문서 쪽 설정 그대로(A4 등).

### 예외와 경계 상황

- 뷰어가 연결되지 않았으면 기존 "뷰어가 없습니다" 오류.
- 아주 큰 문서(수백 쪽)는 시간이 걸린다(#108 측정: 서버 쪽당 약 8~20ms — 실제 공고문 쪽을 되풀이한 300쪽 6.0초 + 뷰어 SVG 쪽당 약 6ms + 전송, 10초 안팎). 뷰어에서 쪽을 20쪽 묶음으로 받고 묶음마다 기존 요청 제한 시간(30초)을 쓴다. 클라이언트가 진행 알림(MCP progress)을 받으면 묶음마다와 PDF 를 만들기 전에 알린다 — MCP 요청 제한 시간은 바꾸지 않는다(ADR 005).
- `.hwp`/`.hwpx` 경로를 주면(덮어쓰기여도) 거부(PDF 로 원본을 덮지 않게).

## 범위 밖

- PDF → HWP 변환(가져오기)
- 인쇄 대화 상자 띄우기, 프린터로 바로 인쇄
- PDF 에 하이라이트·주석 넣기
- 암호 걸린 PDF, PDF/A

## 기술 메모

- 방식(ADR 005, #107 기술 검증): **뷰어**는 쪽마다 `renderPageSvg`(모양) + `getPageTextLayout`(글자·빈칸·자리)을 서버로 보내고, **서버**가 `src/core/pdf-export.ts` `svgPagesToPdf`(pdf-lib + @pdf-lib/fontkit, MIT)로 PDF 를 만들어 쓴다.
  - 글꼴은 서버가 이 컴퓨터의 시스템 글꼴 폴더에서 읽는다(`src/core/pdf-fonts-node.ts`, 맥 내려받는 글꼴 AssetsV2 포함 — 모두 비동기, 처음 내보낼 때 한 번 훑는다, 글꼴 바이트 캐시 96MB 상한 LRU). 뷰어 번들에 글꼴을 넣지 않는다(.mcpb 는 pdf-lib·fontkit 로 +0.67MB, #108).
  - 도구: `src/server/export-pdf-tool.ts`(쪽 범위·묶음 받기·PDF 만들기·쓰기), 뷰어 요청 `export_pdf_pages`(`src/core/pdf-pages.ts` 쪽 SVG·글자 배치, `src/core/screen-fonts.ts` 화면 글꼴 이름).
  - 글꼴 고르기는 SVG `font-family` 차례에서 브라우저처럼(`src/core/pdf-fonts.ts` FontResolver): 있고 그 글자가 있는 첫 글꼴, CSS 굵기 규칙, 없으면 serif·sans-serif 기본 → 기호 글꼴. 넣지 말라는(fsType Restricted) 글꼴은 건너뛴다.
- 탈락: jsPDF + svg2pdf.js(TrueType 만 읽어 맥 고딕이 깨지고 DOM 이 있어야 함), 서버 헤드리스 브라우저 인쇄(.mcpb 에 브라우저를 넣을 수 없음), 뷰어 `window.print()`(사람이 대화 상자에서 골라야 해 도구로 못 씀 — 화면 버튼 보조로만), 쪽 그림(글자 선택 불가).
- 확인 파일: `node scripts/make-pdf-check.ts [폴더] --doc <문서>` (기본 `~/Downloads/docbridge-pdf-check`, 레포에 넣지 않음).
- 저장 경로 규칙은 `save-path.ts` 를 재사용(확장자만 `.pdf`).

## 열린 질문

- ~~PDF 라이브러리와 글꼴 임베드 방식~~ — 결정(#107, ADR 005): pdf-lib 로 쪽 SVG 를 서버에서 직접 그린다. 글자 모양은 화면과 같은 글꼴의 윤곽, 선택·검색은 보이지 않는 글자 층
- ~~시스템 글꼴을 읽을 수 없는 브라우저 환경에서 한글 글꼴을 어디서 얻을지~~ — 결정(#107, ADR 005): PDF 를 서버에서 만들고 서버가 시스템 글꼴 파일을 읽는다(뷰어 번들에 글꼴을 넣지 않음, .mcpb 글꼴 증가 0)
