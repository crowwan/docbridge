# docbridge 디자인

디자인 의도를 적는 문서. **값은 토큰 파일에만 둔다** (Web `src/viewer/tokens.css`).
디자인 카탈로그는 아직 없다(화면이 뷰어 하나뿐). 실제 모습은 `?fixture=<이름>` 개발 화면과 PR 확인 기록 스크린샷으로 본다.

## 컨셉

받은 문서를 원래 모양 그대로 펼쳐 둔 책상. 화면의 주인공은 문서이고, docbridge 의 UI 는 문서 위에 형광펜과 포스트잇 꼬리표, 고친 자리를 두른 테두리, 한 블록을 고칠 때만 잠깐 뜨는 입력칸, 블록을 끌 때의 가로선과 오른쪽 클릭 메뉴를 얹는 정도로만 끼어든다.

## 원칙

- 문서가 주인공이다. 문서 면(흰 종이·검은 글자)의 색과 모양은 건드리지 않고, docbridge 가 얹는 것은 문서와 섞여 보이지 않게 한다.
- 근거 표시는 한 번에 한 묶음만 보인다. 새 하이라이트를 그리면 이전 것은 지운다(PATTERNS F1 과 같은 뜻).
- 바뀐 블록 표시도 한 번에 한 편집 것만 보인다. 다음 편집·하이라이트 때 지운다. 근거(노랑 면)와 고친 자리(초록 테두리)는 같이 보이지 않는다 — 편집은 문서를 다시 그려 하이라이트를 지우고, 하이라이트는 바뀐 블록 표시를 지운다.
- 움직임은 없다. 도구 결과를 받았을 때 이미 그 자리가 보여야 하고, 자동 테스트가 시간에 기대지 않게 한다.
- 문서 위에 얹는 표시는 문서를 가리지 않는다: 하이라이트는 글자를 흐리지 않게 곱하기로 겹치고, 마우스를 막지 않는다. note 는 문서 글자를 덮지 않는 자리를 먼저 찾는다(아래 컴포넌트 표, #51). 입력칸만 예외로 고치는 블록을 덮는다(고치는 동안 그 블록 글자는 입력칸에 있다).
- 실패는 반드시 보인다(PATTERNS F4). 사람 편집이 안 된 이유는 뷰어 아래 알림 하나로, 한 번에 하나만(F1).

## 토큰 역할

### 색

| 토큰 | 역할 | 이유 |
|---|---|---|
| `--bg` | 문서 바깥 바탕 | 흰 쪽이 떠 보이게 옅은 회색 |
| `--surface` | 쪽 면·도구 막대·안내 카드 | 종이색 |
| `--text` | 도구 막대·안내 글자 | 본문 글자 |
| `--muted` | 상태 문구·안내 설명 | 보조 글자(개인 DS 하한 `#666` 보다 진하게) |
| `--highlight` | 근거 하이라이트 면 | 형광펜 노랑. 반투명 + `mix-blend-mode: multiply` 로 겹쳐 검은 글자가 그대로 검다. 문서에 빨강(누름틀 안내문)·파랑이 흔해 그 둘과 겹치지 않는 노랑. 스펙 기본 흐름의 "노란 하이라이트" |
| `--edit-mark` | 바뀐 블록 테두리 색 | "고쳤다·끝났다"의 초록(개인 DS success). 근거 노랑·누름틀 안내문 빨강·파랑 글자와 겹치지 않는다. 흰 쪽 위 대비 약 3.1:1 로 비텍스트 기준 3:1 을 넘는다. 면이 아니라 테두리라 글자를 덮지 않고, 색만이 아니라 모양(두른 선)으로도 하이라이트와 갈린다(PATTERNS A12) |
| `--note-bg` · `--note-fg` | note 꼬리표 면·글자 | 문서 글자(흰 바탕 검은 글자)와 정반대로 진한 면에 흰 글자라 "문서 내용이 아니라 Claude 가 단 말"로 읽힌다. 대비 약 18:1 |
| `--edit-hover` | 마우스 올림 테두리 색 | 개인 DS border-strong(gray-300). "여기를 고칠 수 있다"는 옅은 힌트라 초록(고친 자리)·노랑(근거)과 뜻이 겹치지 않는 회색. 흰 쪽 위 대비 약 1.6:1 로 낮지만, 마우스를 올린 블록에만 보이는 보조 표시이고 고치는 길(더블클릭)은 이것 없이도 된다 |
| `--focus-ring` | 입력칸·메뉴 항목 포커스 링 | 개인 DS ring(= brand-500 파랑). 강조색은 "지금 고르는 것"(포커스·놓일 자리)에만 쓴다. 흰 쪽 위 대비 약 4.5:1 |
| `--drop-line` | 끌어 옮기기 놓일 자리 가로선 | `--focus-ring` 을 따른다. 놓일 자리는 지금 고르는 자리라 포커스와 같은 강조색이고, 초록(고친 자리)·노랑(근거)·회색(마우스 올림)과 겹치지 않는다 |
| `--menu-bg` | 오른쪽 클릭 메뉴 면 | `--surface` 를 따른다(개인 DS bg) |
| `--menu-item-active-bg` | 메뉴 항목 마우스 올림·포커스 면 | 개인 DS bg-subtle(gray-100). 면만으로는 흰 바탕과 대비가 낮아 키보드 포커스는 포커스 링을 같이 그린다 |
| `--menu-disabled-fg` | 앞·뒤 블록이 없어 꺼진 항목(첫 블록 위로, 마지막 블록 아래로) 글자 | 개인 DS fg-disabled(gray-300). 비활성 표시라 본문 대비 기준 밖 |
| `--toast-bg` · `--toast-fg` | 실패 알림 면·글자 | `--note-bg`·`--note-fg` 를 따른다 — note 와 같은 진한 면에 흰 글자(대비 약 18:1). 문서 위에 떠 있는 docbridge 말이라는 같은 뜻이라 같이 바뀐다 |
| `--doc-name-border` | 도구 막대 문서 이름 꼬리표 테두리 | 개인 DS border(gray-300 근처) 옅은 회색. 누를 수 있는 단추로 보이지 않게 면은 칠하지 않고 선만 — 글자(`--muted`)가 이름을 전한다 |
| `--danger` | 실패 알림 왼쪽 선 | 개인 DS error-500. 오류는 색 + 선 + 문장(PATTERNS F5). 진한 면 위 대비 약 4.7:1 |
| `--toast-success-accent` | 성공 알림(PDF 로 저장함) 왼쪽 선 | `--edit-mark` 를 따른다(개인 DS success). 실패 빨강 선과 색·문장 둘 다로 갈린다. 진한 면 위 대비 약 5.9:1 |
| `--toolbar-button-border` | 도구 막대 버튼(PDF) 테두리 | `--edit-hover` 를 따른다(개인 DS border-strong). 문서 이름 꼬리표(`--doc-name-border`)보다 진한 선 + 본문 글자라 눌리는 것으로 보인다 |
| `--toolbar-button-hover-bg` | 도구 막대 버튼 마우스 올림 면 | `--menu-item-active-bg` 를 따른다(개인 DS bg-subtle). 메뉴 항목과 같은 "누를 수 있음" 면 |
| `--toolbar-button-disabled-fg` | 만드는 동안(꺼짐) 버튼 글자 | `--menu-disabled-fg` 를 따른다(개인 DS fg-disabled). 비활성 표시라 본문 대비 기준 밖 |

### 글꼴

| 토큰 | 역할 | 이유 |
|---|---|---|
| `--font-sans` | 뷰어 UI 글꼴 | 시스템 글꼴. 문서 글꼴은 rhwp 가 문서대로 그린다 |

| `--note-font-size` · `--note-line-height` | note 글자 | 14 — 문서 본문(약 13px)과 비슷한 크기라 문서를 덮지 않으면서 읽힌다 |

### 간격, 반경, 그림자

| 토큰 | 역할 | 이유 |
|---|---|---|
| `--space-1`·`2`·`4`·`8` | 4px 단위 간격 | 개인 DS 스케일 그대로 |
| `--note-max-width` | note 최대 폭 | 짧은 말(100자까지)이 두세 줄 안에 들어오고 문서 단 폭(약 570px)의 절반을 넘지 않게 |
| `--note-gap` | note 와 하이라이트·쪽 가장자리·화면 가장자리 사이 | `--space-1`(4px). 붙어 보이되 하이라이트 면과 겹치지 않을 만큼 |
| `--note-min-width` | 쪽 바깥 여백에 둘 note 최소 폭 | 160px — 14px 글자로 한 줄 10자 남짓. 이보다 좁으면 100자 note 가 열 줄을 넘어 읽기 어려워 하이라이트 아래로 보낸다 |
| `--notice-max-width` | 안내 카드 폭 | 한 줄 안내가 읽기 좋은 폭 |
| `--edit-mark-width` | 바뀐 블록 테두리 두께 | 개인 DS `border-w-thick`(선택 상태). 1px 은 표 테두리 선과 헷갈린다 |
| `--edit-mark-offset` | 테두리와 블록 사이 | 글자·표 선에 닿지 않을 만큼만 띄운다. 더 띄우면 위아래 문단 글자를 가린다. 마우스 올림 테두리도 같은 만큼 띄운다 |
| `--edit-hover-width` | 마우스 올림 테두리 두께 | 개인 DS `border-w-thin`. 바뀐 블록 테두리(2px)보다 옅게 |
| `--inline-edit-min-width` | 입력칸 최소 폭 | 160px(note 최소 폭과 같은 값) — 빈 누름틀·한 단어 블록도 열 자 남짓 보이게 |
| `--focus-ring-width` | 입력칸 포커스 링 두께 | 개인 DS `ring-w` |
| `--toast-max-width` | 실패 알림 최대 폭 | 안내 카드와 같은 480px. 좁은 화면에서는 양옆 `--space-4` 를 남긴다 |
| `--drop-line-width` | 놓일 자리 가로선 두께 | 개인 DS `border-w-thick`(선택 상태). 1px 은 표 테두리 선과 헷갈린다 |
| `--drag-threshold` | 끌기 시작 거리(4px, 뷰어 스크립트가 읽는다) | 이만큼 움직여야 끌기 — 클릭·더블클릭(글자 고치기)과 가른다 |
| `--menu-min-width` | 메뉴 최소 폭 | 120px — 두세 글자 항목이 좁아 보이지 않게 |
| `--toast-accent-width` | 실패 알림 왼쪽 오류 선 두께 | 4px — 진한 면 위에서 색만이 아니라 선 모양으로도 "오류"가 보이게 |
| `--doc-name-border-width` | 문서 이름 꼬리표 테두리 두께 | 개인 DS `border-w-thin` |
| `--toolbar-button-height` · `--toolbar-button-border-width` | 도구 막대 버튼 최소 높이·테두리 두께 | 24px(아래 오버라이드)·개인 DS `border-w-thin` |
| `--focus-ring-offset` | 버튼 포커스 링과 버튼 사이 | 2px — 링이 테두리에 붙어 한 선으로 보이지 않게 |
| `--tab-unseen-mark` | 탭 제목 앞 표시 글자(`●`) | 보지 않는 탭에 하이라이트·편집이 생겼다는 표시. 브라우저 탭 제목은 글자만 되므로 작은 채운 원 하나 — 메신저 탭의 안 읽음 표시와 같은 읽힘. 뷰어 스크립트가 읽는다 |
| `--radius-sm` | note 모서리 | 작은 꼬리표(개인 DS 태그 반경) |
| `--radius` | 안내 카드·메뉴 모서리 | 카드(개인 DS md). 메뉴 항목은 `--radius-sm` |
| `--page-shadow` | 쪽·도구 막대·note·입력칸·실패 알림·메뉴 그림자 | 쪽이 종이처럼 떠 보이게. note·입력칸·알림도 같은 그림자로 문서 위에 얹힌 물건처럼. 입력칸은 그림자만 쓰고 테두리를 두지 않는다(PATTERNS X12) — 열려 있는 동안은 포커스 링이 가장자리다 |

| 무엇 | 개인 DS | 이 앱 | 이유 |

## 접근성

- 다크 모드: 따르지 않는다. 문서 면은 종이 그대로(PATTERNS C5 "콘텐츠의 면은 테마를 따르지 않는다"), 뷰어 UI 도 문서에 맞춘다.
- 동작 줄이기: 움직임이 없어 따로 할 것이 없다.
- 대비: note·실패 알림 흰 글자/진한 면 약 18:1. 하이라이트는 곱하기라 글자 대비가 그대로다. 바뀐 블록 테두리/흰 쪽 약 3.1:1(비텍스트 3:1). 입력칸 포커스 링/흰 쪽 약 4.5:1. 마우스 올림 테두리는 보조 표시라 3:1 아래(위 색 표).
- 키보드: 입력칸은 Enter·Esc 로 끝난다. 오른쪽 클릭 메뉴는 메뉴 키·Shift+F10 으로 열고 화살표·Home·End·Enter·Esc 로 다룬다(끌어 옮기기 대신 위로·아래로). 다만 대상 블록은 마우스가 올라가 있는 블록이다 — 블록을 키보드로 고르는 길(그리고 입력칸을 여는 길)은 없다. 이 프로젝트 화면은 마우스 쓰는 데스크톱 브라우저 뷰어 하나뿐이다.
