# docbridge 디자인

디자인 의도를 적는 문서. **값은 토큰 파일에만 둔다** (Web `src/viewer/tokens.css`).
디자인 카탈로그는 아직 없다(화면이 뷰어 하나뿐). 실제 모습은 `?fixture=<이름>` 개발 화면과 PR 확인 기록 스크린샷으로 본다.

## 컨셉

받은 문서를 원래 모양 그대로 펼쳐 둔 책상. 화면의 주인공은 문서이고, docbridge 의 UI 는 문서 위에 형광펜과 포스트잇 꼬리표, 고친 자리를 두른 테두리를 얹는 정도로만 끼어든다.

## 원칙

- 문서가 주인공이다. 문서 면(흰 종이·검은 글자)의 색과 모양은 건드리지 않고, docbridge 가 얹는 것은 문서와 섞여 보이지 않게 한다.
- 근거 표시는 한 번에 한 묶음만 보인다. 새 하이라이트를 그리면 이전 것은 지운다(PATTERNS F1 과 같은 뜻).
- 바뀐 블록 표시도 한 번에 한 편집 것만 보인다. 다음 편집·하이라이트 때 지운다. 근거(노랑 면)와 고친 자리(초록 테두리)는 같이 보이지 않는다 — 편집은 문서를 다시 그려 하이라이트를 지우고, 하이라이트는 바뀐 블록 표시를 지운다.
- 움직임은 없다. 도구 결과를 받았을 때 이미 그 자리가 보여야 하고, 자동 테스트가 시간에 기대지 않게 한다.
- 문서 위에 얹는 표시는 문서를 가리지 않는다: 하이라이트는 글자를 흐리지 않게 곱하기로 겹치고, 마우스를 막지 않는다.

## 토큰 역할

### 색

| 토큰 | 역할 | 이유 |
|---|---|---|
| `--bg` | 문서 바깥 바탕 | 흰 쪽이 떠 보이게 옅은 회색 |
| `--surface` | 쪽 면·도구 막대·안내 카드 | 종이색 |
| `--text` | 도구 막대·안내 글자 | 본문 글자 |
| `--muted` | 상태 문구·안내 설명 | 보조 글자(개인 DS 하한 `#666` 보다 진하게) |
| `--highlight` | 근거 하이라이트 면 | 형광펜 노랑. 반투명 + `mix-blend-mode: multiply` 로 겹쳐 검은 글자가 그대로 검다. 문서에 빨강(누름틀 안내문)·파랑이 흔해 그 둘과 겹치지 않는 노랑. 스펙 기본 흐름의 "노란 하이라이트" |
| `--edit-mark` | 바뀐 블록 테두리 색 | "고쳤다·끝났다"의 초록(개인 DS success). 근거 노랑·누름틀 안내문 빨강·파랑 글자와 겹치지 않는다. 흰 쪽 위 대비 약 3.1:1 로 비텍스트 기준 3:1 을 넘는다. 면이 아니라 테두리라 글자를 덮지 않고, 색만이 아니라 모양(두른 선)으로도 하이라이트와 갈린다(PATTERNS A12) |
| `--note-bg` · `--note-fg` | note 꼬리표 면·글자 | 문서 글자(흰 바탕 검은 글자)와 정반대로 진한 면에 흰 글자라 "문서 내용이 아니라 Claude 가 단 말"로 읽힌다. 대비 약 18:1 |

### 글꼴

| 토큰 | 역할 | 이유 |
|---|---|---|
| `--font-sans` | 뷰어 UI 글꼴 | 시스템 글꼴. 문서 글꼴은 rhwp 가 문서대로 그린다 |
| `--text-size` · `--text-line-height` | 도구 막대·안내 글자 | 개인 DS Caption(14) |
| `--title-size` | 도구 막대 제목·안내 제목 | 16(짝수 규칙) |
| `--note-font-size` · `--note-line-height` | note 글자 | 14 — 문서 본문(약 13px)과 비슷한 크기라 문서를 덮지 않으면서 읽힌다 |

### 간격, 반경, 그림자

| 토큰 | 역할 | 이유 |
|---|---|---|
| `--space-1`·`2`·`4`·`8` | 4px 단위 간격 | 개인 DS 스케일 그대로 |
| `--note-max-width` | note 최대 폭 | 짧은 말(100자까지)이 두세 줄 안에 들어오고 문서 단 폭(약 570px)의 절반을 넘지 않게 |
| `--notice-max-width` | 안내 카드 폭 | 한 줄 안내가 읽기 좋은 폭 |
| `--edit-mark-width` | 바뀐 블록 테두리 두께 | 개인 DS `border-w-thick`(선택 상태). 1px 은 표 테두리 선과 헷갈린다 |
| `--edit-mark-offset` | 테두리와 블록 사이 | 글자·표 선에 닿지 않을 만큼만 띄운다. 더 띄우면 위아래 문단 글자를 가린다 |
| `--radius-sm` | note 모서리 | 작은 꼬리표(개인 DS 태그 반경) |
| `--radius` | 안내 카드 모서리 | 카드(개인 DS md) |
| `--page-shadow` | 쪽·도구 막대·note 그림자 | 쪽이 종이처럼 떠 보이게. note 도 같은 그림자로 문서 위에 얹힌 물건처럼 |

### 모션

| 토큰 | 쓰는 곳 | 이유 |
|---|---|---|
| (없음) | 하이라이트·note 는 바로 나타나고, 첫 대상으로 바로 스크롤한다 | 원칙 "움직임은 없다". 부드러운 스크롤은 결과를 받은 뒤에도 화면이 움직이고 있어 테스트·사용 모두 기다려야 한다 |

### 오버라이드

| 무엇 | 개인 DS | 이 앱 | 이유 |
|---|---|---|---|
| 하이라이트 색 | 상태 색만 있음(경고 주황 등) | 형광펜 노랑 반투명 + 곱하기 | 문서 위 "근거" 라는 뜻의 전용 색. 반투명은 글자가 아니라 면이라 허용(CONCEPT 4-9 맥락 한정), 곱하기라 글자 대비가 떨어지지 않는다 |
| 그림자 | 3~5% 약하게 | 18% (`--page-shadow`) | 회색 바탕 위 흰 쪽 가장자리가 보여야 쪽 경계가 읽힌다. note 도 문서 위에 떠 있어야 해서 같은 값 |
| 글꼴 | Pretendard + Inter | 시스템 글꼴 | 로컬 뷰어라 웹 글꼴을 내려받지 않는다. 문서 글꼴은 rhwp 가 따로 그린다 |
| 자간 | -2%~-3% | 0 | UI 글자가 상태 한 줄뿐이라 따로 맞추지 않음 |

## 컴포넌트

| 컴포넌트 | 언제 쓰나 | 상태 | 접근성 |
|---|---|---|---|
| 하이라이트(`.highlight`) | `highlight` 대상마다 줄·칸·표 사각형 | 있음 / 없음(지움·편집·새 문서·새로고침) | 장식(글자는 캔버스). 마우스를 막지 않음 |
| 바뀐 블록 표시(`.edit-mark`) | 편집 도구 뒤, 바뀐 블록마다 쪽별로 블록 전체(문단 줄들·표·누름틀 값)를 두른 테두리 하나. 안 보이면 그 자리로 바로 스크롤 | 있음 / 없음(다음 편집·하이라이트·되돌리기·새 문서·새로고침, 글자를 모두 지운 빈 문단) | 장식. 바뀐 것은 도구 결과(바뀐 블록 id·글자)로 Claude 가 말로 전한다. 마우스를 막지 않음. 자동 번호("3.")는 rhwp 가 글자 밖에 그려 테두리가 번호 바로 오른쪽을 지난다 |
| note(`.highlight-note`) | `highlight` 에 `note` 가 있을 때, 첫 대상 첫 사각형 바로 위(자리가 없으면 아래)에 왼쪽 맞춤 하나 | 있음 / 없음 | `role="note"`, 글자 그대로 읽힘 |
| 안내 카드(`#notice`) | 토큰 거부·문서 오류 | 보임 / 숨김 | 제목 `h2` |

## 접근성

- 다크 모드: 따르지 않는다. 문서 면은 종이 그대로(PATTERNS C5 "콘텐츠의 면은 테마를 따르지 않는다"), 뷰어 UI 도 문서에 맞춘다.
- 동작 줄이기: 움직임이 없어 따로 할 것이 없다.
- 대비: note 흰 글자/진한 면 약 18:1. 하이라이트는 곱하기라 글자 대비가 그대로다. 바뀐 블록 테두리/흰 쪽 약 3.1:1(비텍스트 3:1).
